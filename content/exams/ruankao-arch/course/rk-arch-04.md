基于架构的软件开发方法 ABSD 是教程里的重点章节，常考“三个基础”“六个过程”“架构需求的来源”。

## 一、ABSD 的特点

ABSD（Architecture-Based Software Design）是**架构驱动**的方法，即由**业务、质量和功能需求的组合**驱动架构设计。

:::key ABSD 的三个基础
1. **功能的分解**：用已有的基于模块的内聚和耦合技术；
2. 通过**选择架构风格**来实现质量和业务需求；
3. **使用软件模板**（如通用的服务模板）。
:::

- ABSD 是**自顶向下、递归细化**的，每次迭代都把概念子系统分解为更小的设计元素；
- 视角和视图：从多个视角（逻辑、进程、部署等）描述架构；
- **用例**描述功能需求，**质量场景**描述质量需求。

## 二、ABSD 的开发过程

:::flow ABSD 的六个过程
架构需求 :: 需求获取 → 标识构件 → 架构需求评审；需求来源是**系统的质量目标、业务目标、开发人员的业务目标**
架构设计 :: 提出架构模型 → 把已标识的构件映射到架构中 → 分析构件之间的相互作用 → 产生架构 → 设计评审
架构文档化 :: 产出**架构规格说明书**和测试架构需求的**质量设计说明书**；文档要从使用者的角度编写，保持最新
架构复审 :: 由外部人员（用户代表、领域专家）参加，标识潜在风险，尽早发现缺陷
架构实现 :: 分析与设计 → 构件实现 → 构件组装 → 系统测试
架构演化 :: 需求变化归类 → 制定演化计划 → 修改、增加或删除构件 → 更新构件间的相互作用 → 构件组装与测试 → 技术评审 → 演化后的架构
:::

:::tip 真题陷阱
架构需求的来源是“系统的质量目标、系统的业务目标、系统开发人员的业务目标”。注意不是“用户的界面偏好”之类。
:::

## 三、架构文档

- 文档的**完整性和质量**是架构成功的关键因素；
- 架构文档要**从使用者角度**编写，分发给所有相关人员，保持较新；
- 文档中有多处重复时，应保持一致。

:::quiz 随堂测验

A. 功能的分解
B. 通过选择架构风格实现质量和业务需求
C. 使用软件模板
D. 编写详细的单元测试
答案：D

B. 系统的业务目标
C. 系统开发人员的业务目标
D. 系统所用编程语言的语法
答案：D
---

A. 编写代码

C. 部署系统
D. 完成验收测试
答案：B
