设计模式每年 1～3 题，先打好基础：**设计原则**和 23 种模式的**分类**，再学 5 种创建型模式。

## 一、面向对象设计原则

| 原则 | 一句话 |
|---|---|
| **单一职责** SRP | 一个类只负责一件事，只有一个引起它变化的原因 |
| **开闭原则** OCP | 对扩展开放，对修改关闭 |
| **里氏替换** LSP | 子类必须能替换父类出现的地方 |
| **依赖倒置** DIP | 依赖抽象，不依赖具体；高层不依赖低层 |
| **接口隔离** ISP | 用多个专门的接口，不用一个臃肿的总接口 |
| **迪米特法则**（最少知识） | 只和直接朋友通信 |
| **组合 / 聚合复用** | 优先用组合，少用继承 |

## 二、23 种模式的分类

| 类别 | 关注 | 模式 |
|---|---|---|
| **创建型**（5） | 对象怎么创建 | 工厂方法、抽象工厂、单例、生成器（建造者）、原型 |
| **结构型**（7） | 类和对象怎么组合 | 适配器、桥接、组合、装饰、外观、享元、代理 |
| **行为型**（11） | 对象之间怎么分工与通信 | 责任链、命令、解释器、迭代器、中介者、备忘录、观察者、状态、策略、模板方法、访问者 |

:::tip 记忆口诀
创建型：“**单抽工建原**”（单例、抽象工厂、工厂方法、建造者、原型）；结构型：“**外桥组装适代享**”（外观、桥接、组合、装饰、适配器、代理、享元）；剩下的都是行为型。
:::

另一个维度：**类模式**（用继承，编译时确定）只有工厂方法、类适配器、解释器、模板方法；其余都是**对象模式**（用组合，运行时可变）。

## 三、创建型模式

| 模式 | 意图 | 典型场景 |
|---|---|---|
| **单例** Singleton | 保证一个类**只有一个实例**，并提供全局访问点 | 配置管理、连接池、日志 |
| **工厂方法** | 定义创建对象的接口，**由子类决定**实例化哪个类 | 日志记录器（文件 / 数据库） |
| **抽象工厂** | 创建**一系列相关或相互依赖的对象**（产品族） | 换皮肤：一套按钮 + 文本框 + 菜单 |
| **生成器（建造者）** | 把复杂对象的**构建过程与表示分离**，同样的过程可以构建不同表示 | 组装电脑、生成复杂报表 |
| **原型** | 通过**复制**已有实例创建新对象 | 创建成本高的对象 |

:::example 辨析
“系统要支持多种风格的界面，每种风格包括按钮、窗口、滚动条一整套控件”——选什么模式？
--- 关键词
“一整套”“一系列相关对象” → 产品族
--- 答案
**抽象工厂**。如果只是“一种产品、由子类决定具体类”，则是工厂方法。
:::

:::quiz 随堂测验
下列属于创建型模式的是：
A. 适配器
B. 原型
C. 观察者
D. 装饰
答案：B
---
“对扩展开放，对修改关闭”是：
A. 单一职责原则
B. 开闭原则
C. 里氏替换原则
D. 依赖倒置原则
答案：B
---
将复杂对象的构建与它的表示分离，使同样的构建过程可以创建不同的表示，是：
A. 抽象工厂
B. 工厂方法
C. 生成器
D. 原型
答案：C
:::

:::cards 记忆卡
开闭原则 :: 对扩展开放，对修改关闭
里氏替换原则 :: 子类可以替换父类出现的任何地方
依赖倒置原则 :: 依赖抽象而不是具体实现
迪米特法则 :: 只与直接朋友通信，又叫最少知识原则
创建型 5 种 :: 单例、工厂方法、抽象工厂、生成器、原型
结构型 7 种 :: 适配器、桥接、组合、装饰、外观、享元、代理
类模式（只有 4 种） :: 工厂方法、类适配器、解释器、模板方法
抽象工厂 :: 创建一系列相关或相互依赖的对象（产品族）
生成器模式 :: 把复杂对象的构建与表示分离
:::
