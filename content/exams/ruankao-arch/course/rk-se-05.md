面向对象的基本概念是 UML、设计模式的基础。综合知识常考“类之间是什么关系”，案例分析常让你补全类图中的关系和多重度。

## 一、面向对象的基本概念

| 概念 | 含义 |
|---|---|
| 对象 | 属性 + 行为，有唯一标识 |
| 类 | 对象的抽象模板；分为**实体类**（存数据）、**边界类**（与外部交互的界面、接口）、**控制类**（协调、控制流程） |
| 封装 | 隐藏内部细节，只暴露接口 |
| 继承 | 子类复用父类的属性和方法 |
| **多态** | 同一消息被不同对象接收产生不同行为；分为通用多态（参数多态、包含多态）和特定多态（过载多态、强制多态） |
| 动态绑定 | 运行时才确定调用哪个方法，是多态的实现基础 |

:::tip 实体类、边界类、控制类
“订单”是实体类；“订单录入界面”“支付接口”是边界类；“下单控制器”是控制类。这是用例分析中常考的划分。
:::

## 二、UML 中类之间的关系

| 关系 | 含义 | 图形 |
|---|---|---|
| **依赖** | 一个类用到另一个类（如作为方法参数），最弱 | 虚线 + 箭头 |
| **关联** | 长期的结构关系，可带多重度（1、0..1、*、1..*） | 实线 |
| **聚合** | 整体与部分，部分可以**独立存在**（班级—学生） | 实线 + **空心菱形**（在整体端） |
| **组合** | 整体与部分，部分**不能独立存在**，同生共死（公司—部门） | 实线 + **实心菱形** |
| **泛化** | 继承关系（一般—特殊） | 实线 + 空心三角 |
| **实现** | 类实现接口 | 虚线 + 空心三角 |

:::key 强弱顺序
依赖 < 关联 < 聚合 < 组合（泛化、实现是另一类关系）。聚合和组合的区别只看一点：**部分能不能离开整体单独存在**。
:::

## 三、面向对象分析与设计

- **OOA**（分析）：认定对象、组织对象、对象间的相互作用、定义对象的操作和属性；
- **OOD**（设计）：设计类、设计交互、设计数据存储、设计界面；
- 面向对象设计原则（单一职责、开闭、里氏替换、依赖倒置、接口隔离、迪米特、组合复用）放在第 7 课。
