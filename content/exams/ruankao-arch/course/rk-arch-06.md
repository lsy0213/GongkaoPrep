构件和中间件考概念：构件的接口与组装、中间件的分类与作用，以及常见的应用服务器和消息中间件。

## 一、构件与连接件

- **构件**：可独立部署的计算单元，通过**接口**与外界交互；接口分**提供接口**（Provided）和**需要接口**（Required）；
- **连接件**：构件之间的交互机制，如过程调用、消息、事件、管道、共享数据、RPC；
- 构件组装的不匹配：**构件本身不匹配**、**连接件不匹配**、**部署时不匹配**；解决办法是**包装器**（Wrapper）、**适配器**、桥接器、中介器。

## 二、中间件

中间件位于**操作系统、网络与应用之间**，屏蔽底层异构性，提供通用服务（通信、事务、安全、负载均衡）。

| 类型 | 说明 | 代表 |
|---|---|---|
| 数据库中间件 | 屏蔽不同数据库的差异 | ODBC、JDBC、MyCat、ShardingSphere |
| **远程过程调用 RPC** | 像调用本地函数一样调用远程服务 | gRPC、Dubbo、Thrift |
| **面向消息的中间件 MOM** | 异步消息传递，**解耦、削峰、异步** | RabbitMQ、Kafka、RocketMQ |
| **分布式对象中间件** | 分布式对象调用 | CORBA、DCOM、Java RMI |
| **事务处理中间件（TP 监视器）** | 分布式事务、负载均衡 | Tuxedo、CICS |
| 应用服务器 | 为 Web 应用提供运行环境 | Tomcat、WebLogic、WebSphere、JBoss |

:::key 消息中间件的作用
**异步通信**（发送方不等待）、**应用解耦**（生产者和消费者互不知道对方）、**流量削峰**（大促时把请求先放队列）、**可靠投递**（持久化、重试、确认）。两种模式：**点对点**（队列，一条消息只被一个消费者消费）和**发布 / 订阅**（主题，一条消息被多个订阅者消费）。
:::

## 三、CORBA 的结构

- **ORB**（对象请求代理）：核心，负责请求的传递；
- **IDL**（接口定义语言）：描述接口，与语言无关；
- **桩 Stub**（客户端代理）和**骨架 Skeleton**（服务端代理）；
- **对象适配器 POA**：连接 ORB 和对象实现。

## 四、构件技术与 Web 服务的比较

传统构件（EJB、COM、CORBA）依赖特定平台或协议；Web 服务和微服务基于 **HTTP + XML / JSON**，跨平台、跨语言，更适合互联网环境集成。
