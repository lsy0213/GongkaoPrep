嵌入式题几乎每年都有一道，背景常是航空、汽车、轨道交通、工业控制。问法比较固定：**实时系统设计、安全关键系统、可靠性设计、软件架构、测试方法**。

## 一、高频问法与答案要点

| 问法 | 答案要点 |
|---|---|
| 嵌入式系统的特点 | 专用性、实时性、资源受限、高可靠、软硬件协同、功耗低 |
| 实时系统 | **硬实时**（错过截止时间即失败，如刹车）vs **软实时**（偶尔错过可接受，如视频）；调度：**优先级抢占**、单调速率 RMS、最早截止期优先 EDF |
| 实时操作系统 RTOS | 可抢占内核、确定性响应、优先级继承（防**优先级反转**）；如 VxWorks、FreeRTOS、μC/OS |
| 安全关键系统设计 | 冗余（双机、三模）、**分区隔离**（ARINC 653）、看门狗、故障检测与降级、形式化验证 |
| 安全性分析 | **FMEA**（自下而上）、**FTA**（自顶向下）、危险分析 |
| 软件可靠性设计 | N 版本程序、恢复块、防卫式编程、异常处理 |
| 嵌入式测试 | 单元测试、**MC/DC 覆盖**（航空 A 级要求）、**硬件在环 HIL** 仿真测试、静态分析 |
| 架构 | 层次化（HAL/BSP、RTOS、中间件、应用）、IMA、AUTOSAR（汽车） |

:::key 优先级反转
低优先级任务持有资源，高优先级任务等待，被中优先级任务抢占，导致高优先级任务被间接阻塞。解决：**优先级继承**（持锁的低优先级任务临时提升到等待者的优先级）、**优先级天花板**。
:::

## 二、答题技巧

- 嵌入式题经常问“**为什么采用某设计**”：从**实时性、可靠性、安全性、资源受限**四个角度作答；
- 问“如何保证系统安全”：**冗余 + 隔离 + 检测 + 降级**四个层次；
- 汽车相关：**AUTOSAR** 分层（应用层、运行时环境 RTE、基础软件层），ISO 26262 功能安全。

:::write 安全关键设计 | 300 | 10
某飞行控制软件要求单点故障不影响飞行安全，且关键任务必须在 10ms 内完成。请从可靠性和实时性两方面说明设计措施。
--- 要点
三模冗余或双余度硬件，多数表决
N 版本程序设计或恢复块等软件容错
分区操作系统（ARINC 653），时间和空间隔离
看门狗与故障检测，故障时切换或降级
采用硬实时 RTOS，基于优先级的抢占式调度
优先级继承防止优先级反转
确定性设计，避免动态内存分配
--- 参考答案
**可靠性**：硬件采用三余度，多数表决屏蔽单点故障；软件采用 N 版本或恢复块容错；分区操作系统使各功能在**时间和空间上隔离**；看门狗监控任务，故障时自动切换或降级。**实时性**：采用硬实时 RTOS，**优先级抢占式调度**（RMS）；资源访问用**优先级继承**防止优先级反转；关键路径避免动态内存分配和不确定的操作，保证**确定性**响应。
:::
