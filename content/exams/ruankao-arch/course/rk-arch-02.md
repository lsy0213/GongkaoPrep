架构风格是**最核心**的考点：综合知识每年 2～4 题，案例分析几乎每年第一题都涉及，论文也常考。先把 Garlan & Shaw 的五大类风格记牢。

## 一、五大类架构风格

| 大类 | 包含的风格 |
|---|---|
| **数据流风格** | **批处理序列**、**管道—过滤器** |
| **调用 / 返回风格** | **主程序 / 子程序**、**面向对象**、**层次结构** |
| **独立构件风格** | **进程通信**、**事件驱动系统（隐式调用）** |
| **虚拟机风格** | **解释器**、**基于规则的系统** |
| **仓库风格（以数据为中心）** | **数据库系统**、**黑板系统**、超文本系统 |

:::tip 口诀
“数据流：批管；调用返回：主面层；独立构件：进事；虚拟机：解规；仓库：数黑超”。
:::

## 二、各风格要点

| 风格 | 特点 | 典型应用 |
|---|---|---|
| 批处理序列 | 每一步处理完**整批数据**才交给下一步 | 传统数据处理、ETL |
| **管道—过滤器** | 数据**流式**经过一个个过滤器，过滤器相互独立；**不适合交互式**系统 | **编译器**（词法→语法→语义→代码生成）、Unix 管道 |
| 面向对象 | 数据和操作封装在对象中 | 一般业务系统 |
| **层次结构** | 每层为上层服务、使用下层服务；可替换某一层；但**性能会损失**，层次难划分 | 网络协议栈、三层架构 |
| **事件驱动（隐式调用）** | 构件不直接调用，而是**发布事件**，由注册了的构件响应；松耦合、易扩展，但**不能控制响应顺序** | GUI、IDE 集成、调试器 |
| **解释器** | 用软件模拟一个虚拟机执行程序；灵活，但效率低 | 脚本语言、**自定义规则** |
| **基于规则的系统** | 规则集 + 规则解释器 + 规则选择器 + 工作内存 | **专家系统**、业务规则频繁变化 |
| 数据库系统 | 以中央数据为中心，构件访问共享数据 | 信息系统 |
| **黑板系统** | 知识源 + 黑板（共享数据）+ 控制；适合**没有确定解法**的问题 | **语音识别**、模式识别、信号处理 |

:::key 案例高频辨析
- **编译器**：传统是管道—过滤器；现代 IDE 中的编译器以**语法树为中心**，是**数据共享（仓库）风格**；
- **语音识别、知识推理**这类没有确定算法的问题 → **黑板**；
- **业务规则经常变化、用户可自定义** → **基于规则的系统**或**解释器**（虚拟机风格）；
- **系统各部分松耦合、通过事件通知** → **隐式调用（事件驱动）**。
:::

## 三、其他常见风格

- **C/S 两层**、**三层 C/S**（表示层、功能层、数据层）、**B/S**、**MVC**、MVP、MVVM；
- **SOA**、**微服务**、**REST**（资源 + HTTP 动词，无状态）、**CQRS**（读写分离）、**事件溯源**；
- **闭环控制**（过程控制）风格：传感器 → 控制器 → 执行器，有反馈回路，用于**机器人、自动驾驶、空调温控**；
- **C2 风格**：构件和连接件都有顶部和底部，按层次连接，构件之间不直接相连。
