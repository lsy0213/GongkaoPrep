摘要、数字签名、数字证书三个概念经常一起考：“用谁的什么密钥”是必考问法。

## 一、消息摘要（哈希）

- 把任意长度的数据变成**固定长度**的摘要，**不可逆**，原文改一点摘要就完全不同；
- 用于**完整性**校验、密码存储（加盐哈希）；
- 算法：**MD5**（128 位，已不安全）、**SHA-1**（160 位，已不安全）、**SHA-256**（256 位）、**SM3**（256 位）。

## 二、数字签名

:::flow 数字签名的过程
发送方 :: 对原文计算摘要 → 用**发送方的私钥**加密摘要，得到签名 → 原文 + 签名一起发送
接收方 :: 用**发送方的公钥**解密签名得到摘要 A → 对收到的原文计算摘要 B → A = B 则验证通过
:::

数字签名保证：**完整性**（没被篡改）、**身份认证**（确实是发送方发的）、**不可抵赖**（发送方无法否认）。注意：数字签名**不保证机密性**。

:::key 一张表记住“用谁的钥匙”
| 目的 | 发送方用 | 接收方用 |
|---|---|---|
| **加密**（机密性） | **接收方的公钥** | 接收方的私钥 |
| **签名**（认证、不可抵赖） | **发送方的私钥** | 发送方的公钥 |
:::

## 三、数字证书与 PKI

- **数字证书**：由 **CA** 签发，把用户身份和**公钥**绑定；遵循 **X.509** 标准；
- 证书内容：版本、序列号、**签名算法**、**颁发者**、有效期、主体、**主体的公钥**，以及 **CA 的数字签名**；
- 验证证书：用 **CA 的公钥**验证证书上的 CA 签名；
- **PKI** 公钥基础设施的组成：**CA**（认证中心，签发证书）、**RA**（注册机构，审核身份）、证书库、**CRL**（证书吊销列表）/ OCSP、密钥备份与恢复。

:::example 一道综合题
用户 A 给 B 发送一封既要保密又要签名的邮件，过程是什么？
--- 签名
A 计算邮件摘要，用 **A 的私钥**签名
--- 加密
A 生成对称密钥加密邮件和签名，再用 **B 的公钥**加密对称密钥
--- 接收
B 用自己的私钥解出对称密钥，解密邮件；用 **A 的公钥**验证签名
:::

## 四、消息认证码 MAC

**HMAC**：用**共享密钥** + 哈希生成认证码，保证完整性和消息来源，但因为双方共享密钥，**不能防抵赖**。

:::quiz 随堂测验
验证 A 的数字签名，应使用：
A. A 的私钥
B. A 的公钥
C. CA 的私钥
D. 接收方的私钥
答案：B
---
数字签名不能保证的是：
A. 完整性
B. 身份认证
C. 不可抵赖
D. 机密性
答案：D
---
验证数字证书真伪使用的是：
A. 证书持有者的私钥
B. 证书持有者的公钥
C. CA 的公钥
D. CA 的私钥
答案：C
:::

:::cards 记忆卡
消息摘要的特点 :: 定长、不可逆、对原文变化敏感
SHA-256 与 SM3 的摘要长度 :: 都是 256 位
数字签名用什么签 :: 发送方的私钥
验证数字签名用 :: 发送方的公钥
数字签名保证的三点 :: 完整性、身份认证、不可抵赖
数字证书绑定了 :: 用户身份和公钥
验证数字证书用 :: CA 的公钥
PKI 的组成 :: CA、RA、证书库、CRL、密钥备份恢复
HMAC 不能防什么 :: 抵赖（双方共享密钥）
:::
