访问控制与安全模型考名字和规则：BLP 的“不上读、不下写”、Biba 的“不下读、不上写”，以及 DAC、MAC、RBAC 的区别。

## 一、访问控制模型

| 模型 | 说明 | 特点 |
|---|---|---|
| **自主访问控制 DAC** | 资源的**所有者**决定谁可以访问 | 灵活，但权限容易扩散；常用**访问控制表 ACL** 或能力表 |
| **强制访问控制 MAC** | **系统**按主体和客体的**安全级别**强制决定 | 严格，用于军事、政府 |
| **基于角色 RBAC** | 权限赋给**角色**，用户被分配角色 | 便于管理，企业系统最常用；支持**最小权限**和**职责分离** |
| 基于属性 ABAC | 根据用户、资源、环境的属性动态决策 | 最灵活 |

## 二、安全模型

:::key BLP 与 Biba（必考）
| 模型 | 保护 | 规则 |
|---|---|---|
| **BLP**（Bell-LaPadula） | **机密性** | **不上读**（不能读更高级别）、**不下写**（不能写到更低级别） |
| **Biba** | **完整性** | **不下读**（不能读更低完整性级别）、**不上写**（不能写到更高级别） |

记忆：两者规则**正好相反**。BLP 防泄密，所以高级信息不能流向低级；Biba 防污染，所以低级数据不能流向高级。
:::

| 其他模型 | 要点 |
|---|---|
| **Chinese Wall**（中国墙） | 防**利益冲突**：访问了一家公司的数据，就不能访问其竞争对手的数据（咨询、金融） |
| **Clark-Wilson** | 保护**商业完整性**，通过良构事务和职责分离 |
| 状态机模型 | 系统从安全状态只能转换到安全状态 |
| 信息流模型 | 控制信息在不同级别之间的流动 |

## 三、身份认证

- 认证因素：**你知道的**（口令）、**你拥有的**（令牌、手机、U 盾）、**你是谁**（指纹、人脸）；同时用两种以上是**多因素认证**；
- **Kerberos**：基于**对称加密**和**可信第三方 KDC**（认证服务器 AS + 票据授予服务器 TGS），用**票据**和**时间戳**防重放；
- **单点登录 SSO**：一次登录访问多个系统。

:::cards 记忆卡
DAC :: 自主访问控制，所有者决定访问权限
MAC :: 强制访问控制，系统按安全级别强制决定
RBAC :: 权限赋给角色，用户分配角色
BLP 模型 :: 保护机密性：不上读、不下写
Biba 模型 :: 保护完整性：不下读、不上写
Chinese Wall 模型 :: 防止利益冲突
认证的三类因素 :: 你知道的、你拥有的、你是谁
Kerberos 的基础 :: 对称加密、可信第三方 KDC、票据和时间戳
:::
