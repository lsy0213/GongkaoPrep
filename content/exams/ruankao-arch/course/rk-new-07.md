大数据架构考 **Lambda 和 Kappa 的对比**，是 2021、2022 年案例分析的原题，论文也考过“论大数据 Lambda 架构”。

## 一、大数据的特征

**5V**：Volume（大量）、Velocity（高速）、Variety（多样）、Value（价值密度低）、Veracity（真实性）。

常用技术：HDFS（分布式文件系统）、MapReduce / **Spark**（批处理）、**Flink** / Storm / Spark Streaming（流处理）、**Kafka**（消息）、HBase、Hive。

## 二、Lambda 架构

:::flow Lambda 的三层
批处理层 Batch Layer :: 存储**全量原始数据**（不可变），定期批量计算，生成**批视图**；准确但延迟高（Hadoop、Spark）
加速层 Speed Layer :: 只处理**最近的增量数据**，实时计算生成**实时视图**；延迟低但可能不精确（Storm、Flink）
服务层 Serving Layer :: **合并批视图和实时视图**，响应查询
:::

- 优点：兼顾**准确性**和**实时性**，容错性好（原始数据不可变，可以重算）；
- 缺点：**同一逻辑要写两套代码**（批处理和流处理），维护成本高；两套系统运维复杂。

## 三、Kappa 架构

- **去掉批处理层**，只保留**流处理**；所有数据都通过消息队列（Kafka）作为流处理；
- 需要重新计算时，从 Kafka 中**重放历史数据**，用新版本的流处理作业重算；
- 优点：**一套代码**，架构简单；
- 缺点：依赖消息队列保存长期数据，**历史数据重算的效率低**，不擅长复杂的批量分析。

:::key Lambda vs Kappa
| | Lambda | Kappa |
|---|---|---|
| 层次 | 批处理层 + 加速层 + 服务层 | 流处理层 + 服务层 |
| 代码 | 两套 | 一套 |
| 复杂度 | 高 | 低 |
| 历史数据处理 | 批处理，效率高 | 重放消息，效率较低 |
| 适合 | 需要大量历史数据分析，又要实时结果 | 以实时为主，历史重算少 |
:::

## 四、其他架构

- **流批一体**：用同一引擎（如 Flink）同时处理流和批，是 Kappa 的发展方向；
- **数据湖**：存储原始格式的海量数据（结构化、半结构化、非结构化），**读时建模**；数据仓库是**写时建模**；
- **湖仓一体**：结合数据湖的灵活和数据仓库的管理能力。
