行为型模式有 11 种，是三类中最多、最容易混的。同样按“意图 + 关键词”记，重点区分观察者、策略、状态、命令、责任链、中介者。

## 一、11 种行为型模式

| 模式 | 意图 | 关键词 |
|---|---|---|
| **观察者** Observer | 定义**一对多**依赖，一个对象状态改变时，所有依赖它的对象都**得到通知**并自动更新 | 订阅、通知、事件、广播 |
| **策略** Strategy | 定义一系列**算法**，封装起来使它们可以**互相替换** | 多种算法、可替换、促销方式 |
| **状态** State | 对象在**内部状态改变时改变行为**，看起来像改了类 | 状态决定行为、订单状态 |
| **命令** Command | 把**请求封装成对象**，支持排队、记录日志、**撤销** | 请求对象化、撤销 / 重做、遥控器 |
| **责任链** Chain of Responsibility | 多个对象都有机会处理请求，**沿链传递**直到有对象处理 | 逐级审批、过滤器链 |
| **中介者** Mediator | 用一个中介对象封装一组对象的交互，使它们**不必相互显式引用** | 多对多变一对多、聊天室、塔台 |
| **模板方法** | 在父类定义**算法骨架**，某些步骤延迟到子类实现 | 固定流程、步骤由子类定 |
| **迭代器** | 顺序访问聚合对象的元素，而**不暴露内部表示** | 遍历 |
| **备忘录** Memento | 不破坏封装的前提下**保存和恢复对象状态** | 快照、存档、撤销 |
| **访问者** Visitor | 在**不改变元素类**的前提下定义作用于这些元素的新操作 | 结构稳定、操作多变 |
| **解释器** | 给定一个语言，定义文法并解释句子 | 规则表达式、简单语言 |

:::key 容易混的几对
- **策略 vs 状态**：策略由**客户主动选**算法；状态由**对象内部状态自动切换**行为；
- **命令 vs 备忘录**：都能做撤销；命令封装的是**操作**，备忘录保存的是**状态**；
- **观察者 vs 中介者**：观察者是一对多的单向通知；中介者把多对多的复杂交互集中管理；
- **责任链**：请求发送者不知道最终由谁处理。
:::

## 二、场景辨析

:::example 判断模式
下面七个场景各是哪种行为型模式？
--- 通知与算法
① 股价变动后，所有关注它的看板自动刷新 → **观察者**
② 商城有满减、打折、返券三种促销，可在运行时切换 → **策略**
--- 请求与撤销
③ 请假 1 天组长批、3 天经理批、7 天总监批 → **责任链**
④ 文本编辑器支持撤销和重做每个操作 → **命令**
--- 状态与协调
⑤ 游戏存档，读档时恢复角色状态 → **备忘录**
⑥ 订单在待支付、已支付、已发货状态下，“取消”操作的行为各不相同 → **状态**
⑦ 飞机之间不直接通信，都通过塔台协调 → **中介者**
:::

## 三、MVC 中的模式

MVC 综合运用了多种模式：模型和视图之间是**观察者**，视图和控制器之间是**策略**，视图的嵌套是**组合**。

:::quiz 随堂测验
将一个请求封装为一个对象，从而可以用不同的请求对客户参数化，并支持可撤销的操作，这是：
A. 命令
B. 策略
C. 备忘录
D. 责任链
答案：A
---
使多个对象都有机会处理请求，避免请求的发送者和接收者之间的耦合，这是：
A. 中介者
B. 责任链
C. 观察者
D. 迭代器
答案：B
---
在不破坏封装性的前提下，捕获一个对象的内部状态并在之后恢复，这是：
A. 原型
B. 状态
C. 备忘录
D. 命令
答案：C
:::

:::cards 记忆卡
观察者模式 :: 一对多依赖，状态变化时通知所有依赖者
策略模式 :: 封装一系列可互相替换的算法
状态模式 :: 内部状态改变时改变行为
命令模式 :: 把请求封装成对象，支持排队、日志、撤销
责任链模式 :: 请求沿链传递，直到有对象处理
中介者模式 :: 用中介对象封装一组对象的交互
模板方法 :: 父类定义算法骨架，子类实现具体步骤
备忘录模式 :: 不破坏封装地保存和恢复对象状态
访问者模式 :: 不改变元素类而定义新操作
MVC 中模型与视图的关系 :: 观察者模式
:::
