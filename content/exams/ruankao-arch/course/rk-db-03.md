数据库设计分六个阶段，每个阶段的产物是常考点；E-R 图转关系模式是综合知识和案例都会考的技能。

## 一、设计的六个阶段

:::flow 数据库设计过程
需求分析 :: 产出**数据流图、数据字典、需求说明书**，作为概念设计的依据
概念结构设计 :: 画 **E-R 图**；合并局部 E-R 图时消除属性冲突、命名冲突、结构冲突
逻辑结构设计 :: E-R 图 → **关系模式**，并做规范化、优化
物理结构设计 :: 确定存储结构、存取方法、**索引、聚簇**、分区
数据库实施 :: 建库、装入数据、试运行
运行与维护 :: 备份恢复、性能监控、重组重构
:::

:::warn 2012 年真题
需求分析阶段形成的是“需求说明文档、数据字典和数据流图”，它们是**概念结构设计**阶段的依据（不是逻辑结构设计）。
:::

## 二、E-R 图

- 实体用矩形、属性用椭圆、联系用菱形；
- 联系的类型：**1:1、1:n、m:n**，以及三个实体之间的多元联系；
- 合并局部 E-R 图的三类冲突：**属性冲突**（同一属性类型、取值范围不同）、**命名冲突**（同名异义、异名同义）、**结构冲突**（同一对象在一处是实体、另一处是属性）。

## 三、E-R 图转关系模式

| 联系 | 转换方法 |
|---|---|
| 1:1 | 可以合并到任意一端的实体关系中（加对方主码作外码），也可以单独成关系 |
| 1:n | 合并到 **n 端**，在 n 端加 1 端的主码作外码 |
| **m:n** | **必须单独成一个关系**，主码是两端主码的组合，加上联系自己的属性 |
| 多元联系 | 单独成关系，主码由各端主码组合 |

:::example 选课
学生（学号、姓名）和课程（课程号、课程名）之间是 m:n 的“选课”联系，带属性“成绩”。转成关系模式？
--- 实体
学生(**学号**, 姓名)；课程(**课程号**, 课程名)
--- 联系
m:n 单独成关系：选课(**学号, 课程号**, 成绩)，学号、课程号分别是外码
--- 结论
共 3 个关系模式。
:::

:::quiz 随堂测验
一个项目可以有多个员工参加，一个员工可以参加多个项目，转换为关系模式时：
A. 把项目号加入员工表
B. 把员工号加入项目表
C. 必须单独建立一个关系模式
D. 不需要转换
答案：C
解析：m:n 联系必须单独成关系（希赛模拟题原型）。
---
E-R 图属于数据库设计的哪个阶段：
A. 需求分析
B. 概念结构设计
C. 逻辑结构设计
D. 物理结构设计
答案：B
:::
