数据仓库考特点和 OLAP；反规范化是案例分析高频点：为了查询性能故意增加冗余，要会说技术手段和带来的问题。

## 一、数据仓库

:::key 数据仓库四个特点
**面向主题、集成的、相对稳定的（非易失）、反映历史变化（随时间变化）**。区别于面向事务、实时更新的业务数据库。
:::

| 对比 | OLTP 联机事务处理 | OLAP 联机分析处理 |
|---|---|---|
| 用户 | 操作人员 | 决策人员、分析师 |
| 数据 | 当前、细节 | 历史、汇总 |
| 操作 | 增删改查，短事务 | 大量只读的复杂查询 |
| 设计 | 规范化 | 星型 / 雪花模型，多维 |

- **ETL**：抽取（Extract）、转换（Transform）、加载（Load），把业务数据装入数据仓库；
- 结构：数据源 → ETL → 数据仓库 / 数据集市 → OLAP 服务器 → 前端工具；
- **OLAP 操作**：切片、切块、**钻取**（下钻到更细粒度 / 上卷汇总）、旋转；
- 实现方式：ROLAP（基于关系库）、MOLAP（基于多维数组）、HOLAP（混合）；
- 多维模型：**星型模型**（一张事实表 + 多张维表）、雪花模型（维表再规范化）。

## 二、数据挖掘

| 任务 | 说明 | 例子 |
|---|---|---|
| **关联分析** | 找同时出现的规律 | 啤酒与尿布 |
| **分类** | 按已知类别给新数据打标签（有监督） | 判断贷款风险 |
| **聚类** | 把相似数据自动分组（无监督） | 客户分群 |
| 预测 / 回归 | 预测连续值 | 销量预测 |
| 序列模式 | 有时间先后的规律 | 先买电脑再买打印机 |

## 三、反规范化

规范化减少冗余，但查询要做很多连接，性能差。**反规范化**是有意引入冗余，用空间换时间。

| 技术手段 | 说明 |
|---|---|
| 增加冗余列 | 在常用表中重复存储另一表的列，免得连接 |
| 增加派生列 | 存储可以计算出来的值，如订单总额 |
| 重新组表 | 把经常一起查的表合并成一张 |
| 分割表 | 水平分割（按行）、垂直分割（按列） |

:::warn 反规范化的代价与对策
带来**数据冗余和不一致**、插入修改更复杂。保持一致的方法：**触发器**（实时）、应用程序同步、**批处理**定期维护、物化视图。
:::

:::example 案例题风格
某电商订单查询需要连接订单、订单明细、商品、用户四张表，高峰期响应慢。数据库层面怎么优化？
--- 反规范化
在订单明细中增加冗余的商品名称、单价；在订单表中增加派生列“订单总额”
--- 一致性
商品名称修改时用触发器或应用层同步，总额在订单写入时计算
--- 其他
建索引、读写分离、热点数据放 Redis 缓存
:::
