NoSQL 和 Redis 是近几年**案例分析**的高频题：比较关系库和 NoSQL、Redis 数据类型、持久化方式、缓存穿透 / 击穿 / 雪崩及其对策、缓存与数据库一致性。

## 一、NoSQL 的四类

| 类型 | 代表 | 适合 |
|---|---|---|
| **键值** | Redis、Memcached | 缓存、会话、计数器 |
| **列族** | HBase、Cassandra | 海量数据、写多读少、按列分析 |
| **文档** | MongoDB | 结构多变的 JSON 文档 |
| **图** | Neo4j | 社交关系、推荐、知识图谱 |

关系库 vs NoSQL：关系库强一致（ACID）、支持复杂查询和事务、扩展靠纵向；NoSQL 模式灵活、**易水平扩展**、高并发高性能，但一般只保证最终一致、复杂查询弱。

## 二、Redis

| 数据类型 | 用途 |
|---|---|
| String | 缓存对象、计数器、分布式锁 |
| Hash | 存对象的多个字段 |
| List | 消息队列、最新列表 |
| Set | 去重、共同好友（交集） |
| **ZSet（有序集合）** | 排行榜 |

- **持久化**：**RDB**（定时快照，恢复快、可能丢最后一段数据）、**AOF**（记录每条写命令，数据更全、文件大恢复慢），两者可以混合使用；
- **集群**：主从复制（读写分离）、**哨兵**（自动故障切换）、Cluster 分片（16384 个哈希槽）；
- Redis 和 Memcached：Redis 数据类型丰富、可持久化、支持主从和集群；Memcached 只有字符串、不持久化、多线程。

## 三、缓存的三大问题

| 问题 | 现象 | 对策 |
|---|---|---|
| **缓存穿透** | 查询**根本不存在**的数据，每次都打到数据库 | 缓存空值、**布隆过滤器**、参数校验 |
| **缓存击穿** | 某个**热点 key 过期**瞬间，大量请求打到数据库 | 互斥锁重建、热点数据永不过期（逻辑过期） |
| **缓存雪崩** | **大量 key 同时过期**或缓存宕机 | 过期时间加随机值、集群高可用、限流降级、多级缓存 |

:::key 缓存与数据库一致性
常用 **Cache Aside**（旁路缓存）：读时先读缓存，没有再读库并写回缓存；写时**先更新数据库，再删除缓存**（不是更新缓存）。要求更高可用“延迟双删”或订阅 binlog 异步删除缓存。
:::

:::example 2022 年案例题风格
某系统用 Redis 缓存商品信息，大促时出现数据库压力激增，日志显示大量请求查询不存在的商品 ID。原因和对策？
--- 判断
查询不存在的数据 → **缓存穿透**
--- 对策
① 对不存在的 key 也缓存一个空值并设短过期时间；② 用布隆过滤器预先过滤不存在的 ID；③ 接口层校验参数合法性。
:::

:::quiz 随堂测验
实现排行榜最合适的 Redis 数据类型是：
A. String
B. List
C. Set
D. ZSet
答案：D
---
大量缓存 key 设置了相同的过期时间，同时失效导致数据库压力骤增，这叫：
A. 缓存穿透
B. 缓存击穿
C. 缓存雪崩
D. 缓存预热
答案：C
---
Cache Aside 模式更新数据时，通常：
A. 先删缓存再更新数据库，且不再处理
B. 先更新数据库，再删除缓存
C. 先更新缓存，再更新数据库
D. 只更新缓存
答案：B
:::

:::cards 记忆卡
NoSQL 四类 :: 键值、列族、文档、图
社交关系用哪类 NoSQL :: 图数据库，如 Neo4j
RDB 持久化 :: 定时快照，恢复快，可能丢数据
AOF 持久化 :: 记录写命令，数据完整，文件大恢复慢
缓存穿透 :: 查不存在的数据；用空值缓存、布隆过滤器
缓存击穿 :: 热点 key 过期；用互斥锁、逻辑过期
缓存雪崩 :: 大量 key 同时过期；过期时间加随机值、高可用、限流
Cache Aside 写操作 :: 先更新数据库，再删除缓存
Redis 哨兵的作用 :: 监控主从并自动故障切换
:::
