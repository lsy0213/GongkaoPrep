UML 2.x 有 14 种图，分为结构图和行为图。考试常问“描述某个方面应该用哪种图”，案例分析常考用例图、类图、顺序图、活动图、状态图的补全。

## 一、14 种图

| 结构图（静态，7 种） | 用途 |
|---|---|
| **类图** | 类、接口及其关系 |
| 对象图 | 某一时刻对象的快照 |
| **构件图（组件图）** | 构件及其依赖、接口 |
| **部署图** | 硬件节点和软件在节点上的部署（物理视图） |
| 包图 | 模型元素的分组 |
| 组合结构图 | 类的内部结构 |
| 制品图 | 文件、库等物理制品 |

| 行为图（动态，7 种） | 用途 |
|---|---|
| **用例图** | 参与者和系统功能（需求） |
| **顺序图（序列图）** | 对象之间按**时间顺序**的消息交互 |
| 通信图（协作图） | 对象之间的**组织结构**和消息 |
| **活动图** | 业务流程、并发（泳道、分叉、汇合） |
| **状态图** | 一个对象的**状态变化**和触发事件 |
| 定时图 | 状态随时间变化的精确时序 |
| 交互概览图 | 活动图和顺序图的混合 |

:::key 顺序图和通信图
二者都是**交互图**，语义等价、可以互相转换：顺序图强调**时间顺序**，通信图强调**对象之间的连接关系**。
:::

## 二、用例图中的关系

| 关系 | 含义 | 例子 |
|---|---|---|
| **包含 include** | 基本用例**一定**要执行被包含的用例，常用于提取公共行为 | “下单”包含“登录” |
| **扩展 extend** | 在特定条件下**可选**地插入扩展用例 | “下单”被“使用优惠券”扩展 |
| 泛化 | 用例或参与者之间的继承 | “网上支付”泛化出“微信支付” |

:::warn 箭头方向
include 箭头从**基本用例指向被包含用例**；extend 箭头从**扩展用例指向基本用例**。
:::

## 三、活动图与状态图

- **活动图**：起点（实心圆）、终点（牛眼）、动作、判断（菱形）、**分叉和汇合**（粗横线，表示并发）、**泳道**（按职责分区）；
- **状态图**：状态、转换、**事件[条件]/动作**；用于描述订单、设备等对象的生命周期。

:::example 选图题
下面四个场景各该用哪种图？
--- 交互与状态
① 描述“用户、ATM、银行系统”在取款时按时间先后的交互 → **顺序图**
② 描述订单从“待支付→已支付→已发货→已完成”→ **状态图**
--- 部署与流程
③ 描述系统部署在哪些服务器上 → **部署图**
④ 描述多部门参与的报销业务流程 → **带泳道的活动图**
:::

:::quiz 随堂测验
描述系统中软件构件在硬件节点上的分布，应使用：
A. 构件图
B. 部署图
C. 包图
D. 类图
答案：B
---
“用户注册”时可选地“上传头像”，二者之间是：
A. include
B. extend
C. 泛化
D. 关联
答案：B
---
强调对象之间消息时间顺序的图是：
A. 通信图
B. 顺序图
C. 状态图
D. 对象图
答案：B
:::

:::cards 记忆卡
UML 结构图 7 种 :: 类图、对象图、构件图、部署图、包图、组合结构图、制品图
UML 行为图 7 种 :: 用例图、顺序图、通信图、活动图、状态图、定时图、交互概览图
顺序图与通信图 :: 都是交互图，前者强调时间顺序，后者强调对象连接
include 关系 :: 基本用例一定执行被包含用例，箭头指向被包含用例
extend 关系 :: 条件满足时可选插入，箭头从扩展用例指向基本用例
活动图表示并发 :: 分叉和汇合（粗横线）
泳道 :: 活动图中按职责划分的区域
状态图转换的写法 :: 事件[条件]/动作
:::
