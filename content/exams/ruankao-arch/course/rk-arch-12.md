可靠性设计考容错技术的分类，特别是 N 版本程序设计和恢复块的区别；也是论文“论软件可靠性设计”的核心素材。

## 一、提高可靠性的途径

| 途径 | 手段 |
|---|---|
| **避错** | 在开发中避免引入错误：规范的过程、形式化方法、评审、测试 |
| **查错** | 发现错误：测试、检测机制 |
| **纠错** | 改正错误 |
| **容错** | 出错后系统仍能正常运行：冗余、恢复 |

## 二、冗余的类型

- **结构冗余**：静态冗余（三模表决、N 版本程序）、动态冗余（主备切换）、混合冗余；
- **信息冗余**：增加校验码（奇偶校验、CRC、海明码）；
- **时间冗余**：重复执行（指令复执、程序回滚）；
- **冗余附加技术**：为实现上述冗余所需的资源和技术（冗余程序、冗余数据等）。

## 三、软件容错技术

| 技术 | 做法 | 特点 |
|---|---|---|
| **N 版本程序设计** | 多个团队**独立开发** N 个功能相同的版本，**同时运行**，**表决**选择结果 | **静态冗余**，前向恢复；要求版本间**设计多样性**，成本高 |
| **恢复块** | 主块执行后做**验收测试**，不通过则**回滚**到检查点，换后备块执行 | **动态冗余**，后向恢复；串行执行 |
| 防卫式程序设计 | 在程序中加入错误检测和处理代码（断言、参数检查、异常处理） | 不需要冗余版本 |

:::key N 版本 vs 恢复块
| | N 版本程序设计 | 恢复块 |
|---|---|---|
| 执行方式 | 并行 | 顺序 |
| 判断机制 | **表决** | **验收测试** |
| 恢复方式 | 前向恢复 | 后向恢复（回滚） |
| 冗余类型 | 静态 | 动态 |
:::

## 四、双机容错与集群

- **双机热备**：一主一备，主机故障时备机接管（心跳检测）；
- **双机互备**：两台都运行各自的服务，互为备份；
- **双机双工**：两台同时运行同一服务、分担负载；
- **集群**：多节点 + 负载均衡 + 故障转移；
- 数据层：数据库主从复制、RAID、异地容灾（RPO、RTO 指标）。

:::tip 容灾的两个指标
**RPO**（恢复点目标）：最多允许丢失多长时间的数据；**RTO**（恢复时间目标）：系统多久之内必须恢复。
:::

C. 防卫式程序设计
D. 检查点
答案：B
