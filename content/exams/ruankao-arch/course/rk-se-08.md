结构型模式有 7 种，关注“类和对象怎么组合成更大的结构”。考试常给一段场景描述问是哪种模式，抓住每种模式的**关键词**即可。

## 一、7 种结构型模式

| 模式 | 意图 | 关键词 |
|---|---|---|
| **适配器** Adapter | 把一个类的接口**转换**成客户希望的另一个接口 | 接口不兼容、转换、旧系统 |
| **桥接** Bridge | 把**抽象部分与实现部分分离**，使它们可以独立变化 | 两个维度独立变化（形状 × 颜色） |
| **组合** Composite | 把对象组合成**树形结构**表示“部分—整体”，使单个对象和组合对象的使用一致 | 树形、文件夹与文件、菜单 |
| **装饰** Decorator | **动态地**给对象**添加职责**，比继承更灵活 | 动态添加功能、层层包装 |
| **外观** Facade | 为子系统中的一组接口提供一个**统一的高层接口** | 简化、统一入口 |
| **享元** Flyweight | 运用共享技术支持**大量细粒度对象** | 大量相似对象、共享、棋子 |
| **代理** Proxy | 为其他对象提供一个**代理以控制对它的访问** | 控制访问、远程代理、虚代理、保护代理 |

:::key 容易混淆的三组
- **适配器 vs 外观**：适配器改变一个已有接口让它能用；外观为一组复杂接口提供一个简单的新接口；
- **装饰 vs 代理**：装饰增加功能（客户知道在增强）；代理控制访问（客户以为在用原对象）；
- **桥接 vs 适配器**：桥接是**设计之初**就分离抽象和实现；适配器是**事后补救**接口不兼容。
:::

## 二、场景辨析

:::example 判断模式
下面七个场景各是哪种结构型模式？
--- 接口与功能
① 已有第三方支付 SDK 的接口和系统定义的支付接口不一致 → **适配器**
② 咖啡可以加奶、加糖、加巧克力，任意组合，运行时决定 → **装饰**
--- 结构与共享
③ 公司组织架构：总公司下有分公司、部门，统一计算人数 → **组合**
④ 文档编辑器中大量字符对象共享字体信息 → **享元**
⑤ 图片很大，先显示占位框，真正需要时才加载 → **代理**（虚代理）
--- 抽象与简化
⑥ 消息有普通、加急两类，发送方式有短信、邮件两种，两个维度都会扩展 → **桥接**
⑦ 家庭影院一键“看电影”：开投影、关灯、开音响 → **外观**
:::

## 三、和设计原则的联系

- 装饰模式体现了**组合复用**和**开闭原则**；
- 外观模式体现了**迪米特法则**；
- 桥接模式用组合代替多层继承，避免类爆炸。

:::quiz 随堂测验
动态地给一个对象添加额外的职责，就增加功能而言比生成子类更灵活，这是：
A. 适配器
B. 装饰
C. 代理
D. 外观
答案：B
---
将抽象部分与其实现部分分离，使它们都可以独立地变化，这是：
A. 桥接
B. 适配器
C. 组合
D. 策略
答案：A
---
为子系统中的一组接口提供一个一致的界面，这是：
A. 外观
B. 中介者
C. 代理
D. 享元
答案：A
:::

:::cards 记忆卡
适配器模式 :: 把一个接口转换成客户期望的另一个接口
桥接模式 :: 抽象与实现分离，各自独立变化
组合模式 :: 树形结构表示部分—整体，单个对象与组合对象使用一致
装饰模式 :: 动态地给对象添加职责
外观模式 :: 为子系统提供统一的高层接口
享元模式 :: 共享技术支持大量细粒度对象
代理模式 :: 提供代理以控制对对象的访问
适配器与桥接的区别 :: 适配器是事后补救，桥接是事先设计
:::
