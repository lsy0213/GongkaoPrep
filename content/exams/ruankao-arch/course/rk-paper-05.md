论文的分数主要在“理论阐述”和“实践论点”两部分。理论要**准确、简练**，实践要**具体、可信、有思考**。

## 一、理论阐述怎么写

- 回答论述要求中的“**主要内容 / 概念 / 分类 / 过程**”；
- 300～400 字，用**条目式**：“ATAM 分为四个阶段：一是……；二是……”；
- 只写和论题直接相关的理论，**不要大段抄教材**；
- 最后一句过渡到项目：“在项目中，我们重点应用了其中的……”

## 二、实践论点怎么写

:::key 一个论点的“五步法”
1. **提出做法**（小标题）：“采用 Redis 缓存提高查询性能”；
2. **说明原因**：项目中遇到了什么问题，有什么需求或约束；
3. **具体实施**：技术方案、关键设计、**方案对比和选择理由**（体现架构师的决策）；
4. **问题与解决**：实施中遇到的困难，怎么解决的；
5. **效果**：用数据说明。
:::

:::example 一段实践论点示范
论题“论软件系统的性能设计”，论点：采用多级缓存提升查询性能。
--- 原因
平台上线初期，医院在高峰期查询参保信息的响应时间超过 3 秒，分析发现 70% 的请求集中在 5% 的热点参保人数据上，数据库成为瓶颈。
--- 实施与决策
我设计了“本地缓存 + Redis”两级缓存：热点数据先查进程内的 Caffeine 缓存，未命中再查 Redis 集群。我们比较过只用 Redis 的方案，由于网络往返仍有约 2 毫秒开销，最终选择两级缓存。缓存更新采用“先更新数据库、再删除缓存”的策略。
--- 问题与效果
上线后出现过热点数据同时过期导致数据库压力骤增的情况，我们为过期时间增加了随机偏移，并对热点 key 使用互斥锁重建。最终高峰期查询响应时间降到 0.5 秒以内，数据库 CPU 使用率从 85% 降到 40%。
:::

## 三、效果、不足与改进

- **效果**：上线时间、运行情况、量化指标，用户评价；
- **不足**：客观写 1～2 点（“由于工期紧，监控体系还不完善”），**不要写致命问题**；
- **改进**：针对不足提出下一步计划。
- 结尾一句升华：“通过该项目，我对……有了更深的理解，在以后的工作中……”
