面向服务的架构 SOA 曾是论文高频主题，现在仍是综合知识和案例的考点：SOA 的特点、ESB、Web 服务的协议栈、REST。

## 一、SOA 的概念

- **服务**：业务功能的独立单元，通过**标准接口**对外提供，与实现技术无关；
- SOA 的特点：**松耦合**、**粗粒度**、**标准化接口**、**位置透明**、**可组合**（服务编排）、可复用；
- SOA 的三种角色：**服务提供者**、**服务请求者**、**服务注册中心**（发布—查找—绑定）。

## 二、Web 服务协议栈

| 协议 | 作用 |
|---|---|
| **SOAP** | 消息格式（基于 XML 的信封），通过 HTTP 等传输 |
| **WSDL** | 描述服务：接口、操作、参数、绑定、地址 |
| **UDDI** | 服务的注册与发现 |
| **BPEL** | 业务流程执行语言，用于**服务编排** |

:::key 服务编排与服务编舞
- **编排（Orchestration）**：有一个**中心控制者**按流程调用各服务（如 BPEL）；
- **编舞（Choreography）**：没有中心，各服务按约定**相互协作**（如 WS-CDL）。
:::

## 三、企业服务总线 ESB

ESB 是 SOA 的基础设施，位于服务之间：
- **消息路由**（基于内容的路由）、**协议转换**（HTTP、JMS、FTP 互转）、**消息格式转换**；
- 服务注册与管理、监控、安全；
- 使服务之间**不直接点对点连接**，降低耦合。

## 四、REST

- 资源用 **URI** 标识，用 HTTP 动词操作：GET 查询、POST 新增、PUT 更新、DELETE 删除；
- **无状态**、可缓存、统一接口、分层系统；
- 数据格式通常是 **JSON**，比 SOAP 轻量，是微服务的主流接口方式。

## 五、SOA 与微服务

| | SOA | 微服务 |
|---|---|---|
| 粒度 | 粗，按业务功能 | 细，按单一职责 |
| 通信 | **ESB** 集中通信，重量级 | 轻量级（**REST、RPC、消息**），去中心化 |
| 数据 | 常共享数据库 | 每个服务**独立数据库** |
| 部署 | 整体或大模块部署 | 每个服务**独立部署**，容器化 |
| 目标 | 企业系统**集成**、复用 | 快速迭代、独立扩展 |

:::cards 记忆卡
SOA 的三种角色 :: 服务提供者、服务请求者、服务注册中心
SOAP :: 基于 XML 的消息格式
WSDL :: 描述 Web 服务的接口和地址
UDDI :: Web 服务的注册与发现
BPEL :: 业务流程执行语言，用于服务编排
ESB 的功能 :: 消息路由、协议转换、格式转换、服务管理
编排与编舞 :: 编排有中心控制者；编舞无中心，各服务协作
REST 的特点 :: 资源用 URI 标识、HTTP 动词操作、无状态
SOA 与微服务通信方式 :: SOA 用 ESB；微服务用轻量级 REST、RPC、消息
:::
