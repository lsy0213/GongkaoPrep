质量属性**战术**是实现质量属性的具体设计手段。案例分析常问“为了提高某质量属性可以采用哪些战术”，综合知识常问“某手段属于哪个属性的战术”。

## 一、各属性的战术

| 质量属性 | 战术 |
|---|---|
| **性能** | 资源需求：**减少计算开销**、减少事件处理量、控制采样频率；资源管理：**引入并发**、**维持多个副本（缓存）**、增加可用资源；资源仲裁：**调度策略**（先进先出、固定优先级、动态优先级） |
| **可用性** | 错误检测：**心跳**、**Ping/Echo**、**异常检测**、投票；错误恢复：**主动冗余（热备）**、**被动冗余（冷备 / 温备）**、备件、**检查点 / 回滚**；错误预防：**从服务中删除**、事务、进程监视器 |
| **安全性** | 抵抗攻击：**身份验证**、**授权**、维护数据**机密性**（加密）、**完整性**、限制暴露、限制访问（防火墙）；检测攻击：**入侵检测**；从攻击中恢复：恢复状态、**审计追踪**识别攻击者 |
| **可修改性** | 局部化修改：**维持语义一致性**、预期期望的变更、泛化模块、限制可能的选择；防止连锁反应：**信息隐藏**、维持现有接口、**使用中介**；推迟绑定时间：**运行时注册**、**配置文件**、多态、组件更换 |
| **可测试性** | 管理输入 / 输出：记录 / 回放、接口与实现分离、特化访问路线；内部监视：**内置监视器** |
| **易用性** | 运行时战术：支持用户主动（**撤销**、取消、聚合）、维护用户模型、维护系统模型；设计时战术：把用户接口与应用分离（**MVC**） |

:::key 高频辨析
- **心跳、Ping/Echo** → 可用性（错误检测）；
- **主动冗余 / 被动冗余** → 可用性（错误恢复）；
- **引入并发、缓存、负载均衡** → 性能；
- **信息隐藏、使用中介、配置文件、运行时注册** → 可修改性；
- **身份验证、授权、加密、审计追踪** → 安全性；
- **撤销、取消** → 易用性。
:::

## 二、主动冗余和被动冗余

| | 主动冗余（热备） | 被动冗余（温备） | 冷备 |
|---|---|---|---|
| 备用节点 | 和主节点**同时处理相同输入**，状态一致 | 主节点处理，**定期同步状态**给备用 | 平时不运行 |
| 切换时间 | 几毫秒 | 秒级～分钟级 | 最长 |
| 成本 | 最高 | 中 | 低 |

## 三、权衡点和敏感点

- **敏感点**：一个设计决策影响**一个**质量属性；
- **权衡点**：一个设计决策影响**多个**质量属性，且影响方向相反（比如加密提高安全性、降低性能）。

:::tip 案例常见权衡
加密 → 安全性↑、性能↓；冗余备份 → 可用性↑、成本↑ 和一致性难度↑；增加中间层（中介）→ 可修改性↑、性能↓；缓存 → 性能↑、一致性↓。
:::

:::quiz 随堂测验
“心跳”战术用于提高：
A. 性能
B. 可用性
C. 安全性
D. 易用性
答案：B
---
通过配置文件在运行时决定加载哪个模块，属于可修改性战术中的：
A. 局部化修改
B. 防止连锁反应
C. 推迟绑定时间
D. 资源仲裁
答案：C
---
对传输数据加密会提高安全性但降低性能，这个设计决策是：
A. 敏感点
B. 权衡点
C. 风险点
D. 非风险点
答案：B
:::

:::cards 记忆卡
性能战术 :: 减少计算开销、引入并发、维持多个副本（缓存）、增加资源、调度策略
可用性的错误检测战术 :: 心跳、Ping/Echo、异常检测
可用性的错误恢复战术 :: 主动冗余、被动冗余、备件、检查点回滚
安全性战术 :: 身份验证、授权、加密、完整性、入侵检测、审计追踪
可修改性战术三类 :: 局部化修改、防止连锁反应、推迟绑定时间
信息隐藏属于 :: 可修改性战术（防止连锁反应）
撤销、取消属于 :: 易用性战术
敏感点 :: 一个决策影响一个质量属性
权衡点 :: 一个决策影响多个质量属性，方向相反
:::
