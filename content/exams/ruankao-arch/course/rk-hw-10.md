嵌入式在架构师考试里分量不小：综合知识每年 2～4 题，案例里常有一道嵌入式 / 安全关键系统的选做题，新教材还单列了“嵌入式系统架构设计”。

## 一、嵌入式系统的特点

- **专用**：为特定应用设计，软硬件可裁剪；
- **实时**：很多系统有严格的时间约束；
- **资源受限**：CPU、内存、功耗、体积都有限；
- **高可靠**：常用于航空、汽车、医疗、工业控制；
- **交叉开发**：在**宿主机**上开发、交叉编译，下载到**目标机**运行和调试。

## 二、软件层次

:::flow 自下而上
硬件层 :: 嵌入式处理器、存储器、I/O 接口
中间层（硬件抽象层 HAL / 板级支持包 BSP） :: 硬件初始化、设备驱动，把操作系统和硬件隔开
系统软件层 :: 实时操作系统 RTOS、文件系统、网络协议栈、图形界面
应用层 :: 具体应用程序
:::

:::key HAL / BSP
- 硬件抽象层**与硬件密切相关**，对操作系统隐藏硬件的差异，使软硬件可以并行设计调试；
- BSP 包括硬件初始化、驱动程序、Bootloader 等，**不包括任务调度**（任务调度是操作系统内核的功能）。
:::

## 三、实时操作系统 RTOS

- **硬实时**：错过截止时间就是失败（如飞控、刹车）；**软实时**：偶尔错过可以容忍（如视频播放）；
- 内核一般是**可抢占的**，基于优先级调度；
- **实时性评价指标**：任务切换时间、中断响应和延迟时间、任务抢占时间、信号量混洗时间、死锁解除时间（“任务执行时间”不是实时性指标）；
- 常见 RTOS：VxWorks、μC/OS、FreeRTOS、RT-Thread、天脉、SylixOS 等。

:::warn 优先级反转
高优先级任务等待低优先级任务占用的资源，而低优先级任务又被中优先级任务抢占，导致高优先级任务被“间接”阻塞。解决办法：**优先级继承**、**优先级天花板**协议。
:::

## 四、安全关键系统

- **DO-178B/C**：机载软件适航标准，软件按失效后果分 A～E 五个等级（A 最严格）；
- **ARINC 653**：分区操作系统标准，**时间分区 + 空间分区**，一个分区出错不影响其他分区；
- 综合模块化航电 **IMA**：多个功能共享计算资源，靠分区隔离；
- 多核处理器的两种模式：**AMP**（非对称，每个核跑不同系统）、**SMP**（对称，一个系统管多个核）。
