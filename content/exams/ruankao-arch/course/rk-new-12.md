DevOps 与持续交付把开发和运维打通，是云原生的配套实践。考概念，也是论文“论 DevOps 及其应用”的素材。

## 一、DevOps

- 目标：打破开发（Dev）与运维（Ops）之间的壁垒，**更快、更可靠**地交付软件；
- 核心：**文化**（协作、共担责任）、**自动化**、**度量**、**分享**（CAMS）；
- 生命周期：计划 → 编码 → 构建 → 测试 → 发布 → 部署 → 运维 → 监控，循环往复。

## 二、CI / CD

| 概念 | 含义 |
|---|---|
| **持续集成 CI** | 开发者频繁（每天多次）把代码合并到主干，每次合并**自动构建和测试** |
| **持续交付** | 在 CI 基础上，代码随时处于**可发布状态**，发布到生产需要**人工批准** |
| **持续部署** | 通过测试后**自动部署到生产**，不需要人工干预 |

:::key 持续交付 vs 持续部署
差别只在最后一步：持续交付**人工点按钮**发布；持续部署**全自动**发布。
:::

## 三、常用工具链

| 环节 | 工具 |
|---|---|
| 代码管理 | Git、GitLab |
| 构建 / CI | Jenkins、GitLab CI、GitHub Actions |
| 制品 | Maven 仓库、Harbor（镜像仓库） |
| 部署 | Docker、Kubernetes、Helm、Ansible |
| 监控 | Prometheus + Grafana、ELK（日志） |

## 四、相关实践

- **基础设施即代码 IaC**：用代码描述服务器、网络等基础设施（Terraform、Ansible），版本化、可重复；
- **不可变基础设施**：服务器部署后不再修改，更新时直接替换新实例；
- **GitOps**：以 Git 仓库为唯一可信源，自动同步到集群；
- **DevSecOps**：把安全融入 DevOps 的每个环节；
- **度量指标**（DORA 四指标）：**部署频率**、**变更前置时间**、**变更失败率**、**故障恢复时间**。

:::quiz 随堂测验

A. 持续集成
B. 持续交付
C. 持续部署
D. 灰度发布
答案：C
---
用代码描述和管理服务器、网络等基础设施的实践是：
A. IaC
B. CI
C. SOA
D. ORM
答案：A
:::
