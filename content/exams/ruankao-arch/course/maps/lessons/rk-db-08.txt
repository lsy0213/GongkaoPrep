# 分布式数据库、CAP 与 BASE
- 分布式数据库
  - 分片透明（最高）：数据是怎么分片的
  - 位置透明：分片存放在哪个场地
  - 局部数据模型透明：各场地用的是什么数据库
- CAP 定理
  - C 一致性：所有节点同一时刻看到相同的数据
  - A 可用性：每个请求都能得到（非错误的）响应
  - P 分区容错：网络分区时系统仍能运行
  - CAP 的取舍
  - CP：牺牲可用性保一致，如 ZooKeeper、HBase、银行转账
  - AP：牺牲强一致保可用，如 Cassandra、Eureka、电商商品浏览
- BASE 理论
  - 基本可用（Basically Available）：出故障时允许损失部分功能或性能，比如降级
  - 软状态（Soft state）：允许中间状态，副本同步可以有延迟
  - 最终一致（Eventually consistent）：经过一段时间，所有副本最终一致
- 分布式事务的实用方案
  - 2PC / 3PC：强一致，性能差，有阻塞问题
  - TCC：Try 预留资源、Confirm 确认、Cancel 取消，业务侵入大
  - 本地消息表 / 可靠消息：业务和消息写在同一个本地事务，消息队列异步投递，最终一致
  - Saga：长事务拆成多个本地事务，失败时执行补偿操作
- 记忆要点
  - 分布式数据库最高级别的透明：分片透明
  - 分片的三个条件：完备性、可重构性、不相交性
  - 两阶段提交的缺点：协调者故障时参与者阻塞，性能差
  - CAP 三个字母：一致性、可用性、分区容错性
  - CP 系统例子：ZooKeeper、HBase
  - AP 系统例子：Cassandra、Eureka
