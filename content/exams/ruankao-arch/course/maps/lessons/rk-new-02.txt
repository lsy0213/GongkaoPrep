# 层次式架构：表现层、业务层与持久层
- 典型的四层 / 五层结构
  - 表现层：展示数据、接收用户输入；MVC、MVP、MVVM、Vue、React
  - 中间层（业务逻辑层）：业务规则、业务流程、事务控制；Spring、业务构件、工作流
  - 数据访问层（持久层）：屏蔽数据库差异，提供数据操作
  - 数据层：存储数据；关系数据库、NoSQL、文件
- 表现层框架
  - MVC：模型（数据和业务）、视图（展示）、控制器（接收请求、调度）；视图可以直接读取模型
  - MVP：Presenter 代替 Controller，视图和模型完全隔离
  - MVVM：ViewModel 和视图之间双向数据绑定
  - 案例常考的 MVC 职责
- 数据访问层
  - ORM（对象关系映射）：把对象和关系表映射，开发者面向对象编程
  - DAO 模式：把数据访问封装在 DAO 对象中，业务层不直接写 SQL，换数据库只改 DAO
- 物联网和其他层次结构
  - 物联网三层：感知层（传感器、RFID）→ 网络层（传输）→ 应用层
  - 层次式架构的优点：结构清晰、关注点分离、易于替换和复用；缺点：层次多影响性能
- 记忆要点
  - 层次式架构的四层：表现层、业务逻辑层、数据访问层、数据层
  - MVC 三部分：模型、视图、控制器
  - MVP 的特点：视图和模型完全隔离，便于测试
  - MVVM 的特点：视图和 ViewModel 双向数据绑定
  - Hibernate 与 MyBatis：Hibernate 全自动 ORM
  - DAO 模式：封装数据访问，业务层不直接写 SQL
