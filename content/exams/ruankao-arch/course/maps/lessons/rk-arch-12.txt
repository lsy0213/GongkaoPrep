# 可靠性设计：容错与冗余
- 提高可靠性的途径
  - 避错：在开发中避免引入错误：规范的过程、形式化方法、评审、测试
  - 查错：发现错误：测试、检测机制
  - 纠错：改正错误
  - 容错：出错后系统仍能正常运行：冗余、恢复
- 冗余的类型
  - 结构冗余：静态冗余（三模表决、N 版本程序）、动态冗余（主备切换）、混合冗余
  - 信息冗余：增加校验码（奇偶校验、CRC、海明码）
  - 时间冗余：重复执行（指令复执、程序回滚）
  - 冗余附加技术：为实现上述冗余所需的资源和技术（冗余程序、冗余数据等）
- 软件容错技术
  - N 版本程序设计：多个团队独立开发 N 个功能相同的版本，同时运行，表决选择结果
  - 恢复块：主块执行后做验收测试，不通过则回滚到检查点，换后备块执行；动态冗余，后向恢复
  - 防卫式程序设计：在程序中加入错误检测和处理代码（断言、参数检查、异常处理）；不需要冗余版本
  - N 版本 vs 恢复块
  - 执行方式：并行；顺序
  - 判断机制：表决；验收测试
  - 恢复方式：前向恢复；后向恢复（回滚）
  - 冗余类型：静态；动态
- 双机容错与集群
  - 双机热备：一主一备，主机故障时备机接管（心跳检测）
  - 双机互备：两台都运行各自的服务，互为备份
  - 双机双工：两台同时运行同一服务、分担负载
  - 集群：多节点 + 负载均衡 + 故障转移
  - 容灾的两个指标
- 记忆要点
  - 提高可靠性的四条途径：避错、查错、纠错、容错
  - 冗余的类型：结构冗余、信息冗余、时间冗余、冗余附加技术
  - N 版本程序设计：独立开发多个版本、并行运行、表决，静态冗余
  - 恢复块：验收测试不通过就回滚换后备块，动态冗余
  - N 版本与恢复块的判断机制：表决 vs 验收测试
  - 防卫式程序设计：在程序中加入检测和处理错误的代码
