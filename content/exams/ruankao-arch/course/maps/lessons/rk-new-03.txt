# Web 架构：负载均衡、缓存与高并发
- 单台服务器到集群的演进
- 负载均衡
  - DNS 负载均衡：一个域名解析到多个 IP，粗粒度
  - 四层（传输层）：按 IP + 端口转发，如 LVS，性能高
  - 七层（应用层）：按 URL、Cookie 等内容转发，如 Nginx，更灵活
  - 硬件：F5
  - 会话保持的方法
- 缓存体系
- 数据库扩展
  - 读写分离：主库写、从库读，主从复制（异步复制有延迟，要处理读到旧数据的问题）
  - 分库分表：垂直拆分（按业务拆库、按列拆表）、水平拆分（按行，按 ID 哈希或范围路由）
  - 分库分表带来的问题：分布式事务、跨库 JOIN、全局唯一 ID（雪花算法）、分页排序
- 高可用手段
  - 限流（令牌桶、漏桶）、降级（关闭非核心功能）、熔断（下游故障时快速失败）
  - 异步化：消息队列削峰
  - 静态化：热点页面生成静态 HTML
- 记忆要点
  - 四层与七层负载均衡：四层按 IP 端口转发（LVS）；七层按内容转发（Nginx）
  - 负载均衡常用算法：轮询、加权轮询、最少连接、源地址哈希、一致性哈希
  - 集群中会话保持最常用的方法：把 Session 集中存储到 Redis
  - CDN 的作用：静态资源就近访问，减轻源站压力
  - 垂直拆分与水平拆分：垂直按业务或列拆；水平按行拆
  - 分库分表的问题：分布式事务、跨库 JOIN、全局 ID、分页排序
