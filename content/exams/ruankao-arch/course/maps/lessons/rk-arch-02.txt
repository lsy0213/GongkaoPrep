# 经典架构风格
- 五大类架构风格
  - 数据流风格：批处理序列、管道—过滤器
  - 调用 / 返回风格：主程序 / 子程序、面向对象、层次结构
  - 独立构件风格：进程通信、事件驱动系统（隐式调用）
  - 虚拟机风格：解释器、基于规则的系统
  - 仓库风格（以数据为中心）：数据库系统、黑板系统、超文本系统
  - 口诀
- 各风格要点
  - 批处理序列：每一步处理完整批数据才交给下一步；传统数据处理、ETL
  - 管道—过滤器：数据流式经过一个个过滤器，过滤器相互独立；不适合交互式系统
  - 面向对象：数据和操作封装在对象中；一般业务系统
  - 层次结构：每层为上层服务、使用下层服务；可替换某一层；但性能会损失，层次难划分
  - 事件驱动（隐式调用）：构件不直接调用，而是发布事件，由注册了的构件响应；松耦合、易扩展
  - 解释器：用软件模拟一个虚拟机执行程序；灵活，但效率低；脚本语言、自定义规则
  - 基于规则的系统：规则集 + 规则解释器 + 规则选择器 + 工作内存
  - 数据库系统：以中央数据为中心，构件访问共享数据；信息系统
- 其他常见风格
  - C/S 两层、三层 C/S（表示层、功能层、数据层）、B/S、MVC、MVP、MVVM
  - SOA、微服务、REST（资源 + HTTP 动词，无状态）、CQRS（读写分离）、事件溯源
  - 闭环控制（过程控制）风格：传感器 → 控制器 → 执行器，有反馈回路
  - C2 风格：构件和连接件都有顶部和底部，按层次连接，构件之间不直接相连
- 记忆要点
  - 黑板系统适用：没有确定解法的问题，如语音识别、模式识别
  - 现代编译器的风格：以语法树为中心的数据共享风格
  - 业务规则频繁变化选：基于规则的系统（虚拟机风格）
