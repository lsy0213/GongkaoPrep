# 软件架构的概念与 4+1 视图
- 什么是软件架构
  - 软件架构是系统的高层结构：由构件、构件之间的连接件，以及指导它们设计和演化的约束与原则组成
  - 架构设计在需求分析之后、详细设计之前，是需求到实现的桥梁
  - 软件架构的作用
  - 是项目干系人之间沟通的手段
  - 体现了最早的设计决策，最难修改、影响最大
  - 是可传递、可复用的模型（产品线的基础）
  - 决定系统能否满足质量属性（性能、可用性、安全性……）
  - 可以在早期评估、预测系统质量，降低风险
- Kruchten 的 4+1 视图
  - 逻辑视图：系统的功能（对象和类）；最终用户
  - 开发视图（实现视图）：软件模块的组织、分层、子系统；程序员
  - 进程视图：并发、同步、性能、可伸缩、容错；系统集成人员
  - 物理视图（部署视图）：软件到硬件的映射、拓扑、安装；系统工程师
  - 场景视图（用例视图，“+1”）：用例，串起其他四个视图并验证；所有人
  - 判断技巧
- 其他架构描述方法
  - IEEE 1471 / ISO/IEC/IEEE 42010：用“视点
  - 架构的生命周期：需求 → 设计 → 文档化 → 评估 → 实现 → 演化
- 记忆要点
  - 软件架构的组成：构件、连接件、约束
  - 架构设计在开发中的位置：需求分析之后、详细设计之前
  - 4+1 视图的五个视图：逻辑、开发、进程、物理、场景（用例）
  - 逻辑视图关注：系统的功能，面向最终用户
  - 开发视图关注：软件模块组织，面向程序员
  - 进程视图关注：并发、同步、性能
