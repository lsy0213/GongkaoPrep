# ABSD：基于架构的软件开发
- ABSD 的特点
  - ABSD 的三个基础
  - 功能的分解：用已有的基于模块的内聚和耦合技术
  - 通过选择架构风格来实现质量和业务需求
  - 使用软件模板（如通用的服务模板）
  - ABSD 是自顶向下、递归细化的，每次迭代都把概念子系统分解为更小的设计元素
  - 用例描述功能需求，质量场景描述质量需求
- ABSD 的开发过程
  - 架构需求：需求获取 → 标识构件 → 架构需求评审
  - 架构设计：提出架构模型 → 把已标识的构件映射到架构中 → 分析构件之间的相互作用 → 产…
  - 架构文档化：产出架构规格说明书和测试架构需求的质量设计说明书；文档要从使用者的角度编写
  - 架构复审：由外部人员（用户代表、领域专家）参加，标识潜在风险，尽早发现缺陷
  - 架构实现：分析与设计 → 构件实现 → 构件组装 → 系统测试
  - 架构演化：需求变化归类 → 制定演化计划 → 修改等
  - 真题陷阱
- 架构文档
  - 文档的完整性和质量是架构成功的关键因素
  - 架构文档要从使用者角度编写，分发给所有相关人员，保持较新
- 记忆要点
  - ABSD 由什么驱动：业务、质量和功能需求的组合
  - ABSD 的三个基础：功能分解、选择架构风格、使用软件模板
  - ABSD 的六个过程：架构需求、设计、文档化、复审、实现、演化
  - 架构需求的来源：系统质量目标、系统业务目标、开发人员的业务目标
  - 架构文档化的产出：架构规格说明书和质量设计说明书
  - 架构复审的参与者：外部人员，如用户代表、领域专家
