Web 架构是近几年**案例分析的必考题**：高并发、高可用的手段——负载均衡、缓存、读写分离、分库分表、CDN、消息队列、限流降级。

## 一、单台服务器到集群的演进

单机 → 应用与数据分离 → 加缓存 → **应用集群 + 负载均衡** → **数据库读写分离** → CDN 和反向代理 → **分库分表** → 业务拆分（微服务）→ 分布式消息、搜索、NoSQL。

## 二、负载均衡

| 层次 | 技术 |
|---|---|
| DNS 负载均衡 | 一个域名解析到多个 IP，粗粒度 |
| **四层**（传输层） | 按 IP + 端口转发，如 LVS，性能高 |
| **七层**（应用层） | 按 URL、Cookie 等内容转发，如 **Nginx**，更灵活 |
| 硬件 | F5 |

算法：**轮询**、加权轮询、**最少连接**、**源地址哈希**（同一用户落在同一台，保持会话）、一致性哈希。

:::key 会话保持的方法
① **会话粘滞**（IP 哈希）；② **会话复制**（服务器之间同步）；③ **集中存储 Session**（Redis，最常用）；④ **Token / JWT**（无状态，服务端不存）。
:::

## 三、缓存体系

浏览器缓存 → **CDN**（静态资源就近访问）→ **反向代理缓存**（Nginx）→ **应用本地缓存** → **分布式缓存**（Redis）→ 数据库缓存。缓存三大问题（穿透、击穿、雪崩）见数据库课程第 9 课。

## 四、数据库扩展

- **读写分离**：主库写、从库读，主从复制（异步复制有延迟，要处理**读到旧数据**的问题）；
- **分库分表**：**垂直拆分**（按业务拆库、按列拆表）、**水平拆分**（按行，按 ID 哈希或范围路由）；
- 分库分表带来的问题：**分布式事务**、跨库 JOIN、全局唯一 ID（雪花算法）、分页排序；
- 中间件：ShardingSphere、MyCat。

## 五、高可用手段

- **限流**（令牌桶、漏桶）、**降级**（关闭非核心功能）、**熔断**（下游故障时快速失败）；
- **异步化**：消息队列削峰；
- 冗余：多机房、异地多活；
- **静态化**：热点页面生成静态 HTML。

:::example 秒杀系统（案例高频）
设计秒杀系统应采取哪些措施？
--- 前端
页面静态化 + CDN；按钮防重复点击；验证码分流
--- 接入层
Nginx 负载均衡，**限流**；恶意请求过滤
--- 服务与数据
**Redis 预扣库存**（原子操作），扣减成功的请求进入**消息队列**异步下单；数据库最终扣减；防超卖
:::

:::quiz 随堂测验
根据 URL 内容转发请求的负载均衡工作在：
A. 二层
B. 三层
C. 四层
D. 七层
答案：D
---
同一用户的请求总是被转发到同一台服务器，应采用的负载均衡算法是：
A. 轮询
B. 最少连接
C. 源地址哈希
D. 随机
答案：C
---
数据库读写分离后，可能出现的问题是：
A. 写入速度变慢
B. 由于主从复制延迟读到旧数据

D. 无法备份

:::cards 记忆卡
四层与七层负载均衡 :: 四层按 IP 端口转发（LVS）；七层按内容转发（Nginx）
负载均衡常用算法 :: 轮询、加权轮询、最少连接、源地址哈希、一致性哈希
集群中会话保持最常用的方法 :: 把 Session 集中存储到 Redis
CDN 的作用 :: 静态资源就近访问，减轻源站压力
垂直拆分与水平拆分 :: 垂直按业务或列拆；水平按行拆
分库分表的问题 :: 分布式事务、跨库 JOIN、全局 ID、分页排序
限流算法 :: 令牌桶、漏桶
熔断 :: 下游故障时快速失败，防止雪崩
:::
