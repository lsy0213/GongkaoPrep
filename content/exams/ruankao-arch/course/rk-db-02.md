数据库的三级模式和两级映像是理解“数据独立性”的钥匙；关系模型的术语和完整性约束是后面范式、SQL 的基础。

## 一、三级模式、两级映像

| 模式 | 又叫 | 对应 |
|---|---|---|
| 外模式 | 子模式、用户模式 | 用户看到的视图，可以有多个 |
| **概念模式** | 模式、逻辑模式 | 全体数据的逻辑结构（表），只有一个 |
| 内模式 | 存储模式 | 物理存储方式（索引、存储文件），只有一个 |

:::key 两级映像 → 两种独立性
- **外模式 / 模式映像** → **逻辑独立性**：表结构改了，只改映像，应用程序不用改；
- **模式 / 内模式映像** → **物理独立性**：存储方式改了（加索引、换文件组织），表结构和应用不用改。
:::

:::tip 真题陷阱
“建聚簇索引改变的是哪一级？”——聚簇索引改变数据的物理存储顺序，改的是**内模式**（2022 年真题）。
:::

## 二、数据模型

- **概念模型**：E-R 图，和具体数据库无关；
- **逻辑模型**：层次、网状、**关系**、面向对象模型；
- **物理模型**：数据在存储介质上的组织。

## 三、关系模型的术语

| 术语 | 含义 |
|---|---|
| 关系 | 一张二维表 |
| 元组 | 一行 |
| 属性 | 一列 |
| 域 | 属性的取值范围 |
| 候选码（候选键） | 能唯一标识元组、且没有多余属性的属性组 |
| 主码（主键） | 选定的一个候选码 |
| 主属性 | 包含在**任何一个**候选码中的属性 |
| 外码（外键） | 本表中引用另一张表主码的属性 |
| 全码 | 所有属性一起才构成码 |

## 四、完整性约束

- **实体完整性**：主码不能为空、不能重复；
- **参照完整性**：外码要么为空，要么等于被参照表中某个主码值；
- **用户定义完整性**：如“工资必须在 2000～50000 之间”，用 CHECK 或**触发器**实现。

:::example 用什么实现约束
职务表 P(职务, 最低工资, 最高工资)，员工表 EMP(员工号, 职务, 工资)，要求员工工资在职务对应的范围内，用什么实现？
--- 分析
这个约束跨两张表、要比较数值，参照完整性只能保证“职务存在”，做不到比较工资范围。
--- 答案
在 **EMP 上建触发器**，插入或修改工资时检查（希赛模拟题）。
:::

:::quiz 随堂测验
数据的物理独立性是通过什么保证的：
A. 外模式 / 模式映像
B. 模式 / 内模式映像
C. 外模式
D. 视图
答案：B
---
主码不能为空，属于：
A. 实体完整性
B. 参照完整性
C. 用户定义完整性
D. 域完整性
答案：A
:::
