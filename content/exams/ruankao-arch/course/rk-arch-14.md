这一课把“系统架构设计”收个尾：架构师做什么、架构决策怎么做和怎么记录。这些内容在论文的“我的角色”和“架构决策”部分非常有用。

## 一、架构师的职责

- **需求**：参与需求分析，特别是识别**关键质量属性**和约束；
- **技术选型**：选择架构风格、框架、中间件、数据库；
- **架构设计**：划分子系统和构件，定义接口，形成架构文档；
- **评估与评审**：组织架构评估（ATAM），评审设计；
- **指导实现**：把架构传达给开发团队，监督实现与架构的一致性；
- **沟通协调**：在客户、产品、开发、测试、运维之间沟通，**平衡各方关注点**；
- **持续演化**：根据变化调整架构，控制技术债务。

## 二、架构决策

:::key 架构决策的要素
**问题**（要解决什么）→ **候选方案** → **评估标准**（质量属性、成本、团队能力、时间）→ **决策**及**理由** → **影响和权衡**。
:::

- 用 **ADR（架构决策记录）** 记录：标题、状态、背景、决策、后果；
- 决策常见的权衡：性能 vs 可修改性、一致性 vs 可用性（CAP）、成本 vs 可靠性、开发速度 vs 质量；
- 好的决策：**基于质量属性**、可追溯到需求、考虑团队能力和成本、留有演化空间。

## 三、架构设计的一般过程

:::flow 一般过程
识别关键需求 :: 功能需求 + 质量属性场景 + 约束
选择架构风格 :: 根据质量属性选择一种或组合多种风格
划分结构 :: 子系统、构件、接口、部署
运用战术 :: 针对每个关键质量属性设计具体战术（缓存、冗余、加密、中介……）
评估 :: ATAM 等方法评估，识别风险和权衡
文档化与演化 :: 4+1 视图、ADR；随需求变化持续演化
:::

## 四、论文中的“我的角色”

:::example 论文开头的角色描述
怎样写才像一个架构师？
--- 不好的写法
“我在项目中负责编码和测试工作。”——这不是架构师
--- 好的写法
“我在该项目中担任**系统架构师**，负责需求中质量属性的分析、整体架构设计和技术选型，组织了架构评估，并指导开发团队按架构实施。”
:::

:::quiz 随堂测验
下列不属于架构师主要职责的是：
A. 识别关键质量属性
B. 进行技术选型
C. 组织架构评估
D. 编写每个模块的全部代码
答案：D
---
记录架构决策时，最重要的是写清楚：
A. 决策者的姓名
B. 背景、决策、理由和后果
C. 代码行数
D. 会议地点
答案：B
:::
