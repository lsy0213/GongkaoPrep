微服务是近年**案例和论文最热门**的主题：微服务的特点、拆分原则、核心组件（注册中心、网关、配置中心、熔断）、带来的问题和对策。

## 一、微服务的特点

- 把单体应用拆成一组**小的、自治的服务**，每个服务围绕**业务能力**构建；
- **独立开发、独立部署、独立扩展**，可以用不同的技术栈；
- 每个服务**独立数据库**（去中心化数据管理）；
- 轻量级通信：REST、gRPC、消息队列；
- 自动化部署：CI/CD + 容器。

## 二、微服务的核心组件

| 组件 | 作用 | 常见实现 |
|---|---|---|
| **服务注册与发现** | 服务启动时注册，调用方从注册中心获取地址 | Eureka、Nacos、Consul、ZooKeeper |
| **API 网关** | 统一入口：**路由、鉴权、限流、协议转换、聚合** | Spring Cloud Gateway、Kong、Zuul |
| **配置中心** | 集中管理配置，动态刷新 | Nacos、Apollo、Spring Cloud Config |
| **熔断 / 降级** | 下游故障时快速失败，防止**雪崩** | Hystrix、Sentinel、Resilience4j |
| 负载均衡 | 客户端负载均衡 | Ribbon、LoadBalancer |
| **链路追踪** | 追踪一个请求经过的所有服务 | SkyWalking、Zipkin、Jaeger |
| 服务间调用 | 声明式 HTTP 客户端 / RPC | OpenFeign、Dubbo、gRPC |

## 三、服务拆分原则

- 按**业务能力**或**领域驱动设计 DDD 的限界上下文**拆分；
- **单一职责**、高内聚低耦合；
- 避免**过度拆分**（服务太多运维成本高、调用链长）；
- 考虑团队结构（**康威定律**：系统结构反映组织的沟通结构）。

## 四、微服务带来的问题与对策

| 问题 | 对策 |
|---|---|
| **分布式事务** | Saga、TCC、可靠消息最终一致（见数据库第 8 课） |
| 服务调用链长、故障传播 | **熔断、降级、限流、超时重试** |
| 运维复杂 | **容器化 + Kubernetes**、自动化部署、集中日志（ELK）、监控（Prometheus） |
| 问题定位难 | **链路追踪**、集中日志 |
| 接口版本兼容 | API 版本管理、契约测试 |
| 数据一致性和查询 | CQRS、事件驱动、数据冗余 |

:::key 服务网格 Service Mesh
把服务治理（熔断、限流、加密、追踪）从业务代码中剥离，放到**边车代理 Sidecar**（如 Istio + Envoy）中，业务代码不感知。数据平面是 Sidecar，控制平面统一下发策略。
:::

:::example 案例题：单体改微服务
某单体电商系统发布慢、扩展难，拟改为微服务，请说明思路。
--- 拆分
按业务拆分为用户、商品、订单、库存、支付等服务，每个服务独立数据库
--- 治理
Nacos 做注册和配置中心；Gateway 做统一入口、鉴权、限流；Sentinel 熔断降级；SkyWalking 链路追踪
--- 一致性与部署
下单涉及订单、库存、支付，用可靠消息或 Saga 保证最终一致；Docker + Kubernetes 部署，CI/CD 流水线
:::

:::quiz 随堂测验

答案：B
