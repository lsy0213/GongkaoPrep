大数据与新技术题：Lambda / Kappa 架构对比、数据湖、物联网架构、AI 应用架构。前两年的原题就是 Lambda 和 Kappa 的对比，务必背熟。

## 一、Lambda vs Kappa（必背）

| 维度 | Lambda | Kappa |
|---|---|---|
| 结构 | 批处理层 + 加速层 + 服务层 | 只有流处理层（+ 服务层） |
| 代码 | 批、流两套，**维护复杂** | 一套，**简单** |
| 实时性 | 加速层保证实时 | 天然实时 |
| 准确性 | 批处理层重算，**准确** | 依赖流处理和重放 |
| 历史数据重算 | 批处理效率高 | 重放消息，**效率较低** |
| 适用 | 历史数据分析量大，又要实时结果 | 实时为主、算法变更少 |

:::example 2021 年案例题风格
某网站要做用户行为分析，既要实时大屏（秒级），又要按月做复杂的用户画像分析，选 Lambda 还是 Kappa？
--- 分析
实时大屏需要流处理；月度画像需要对海量历史数据做复杂批量计算
--- 结论
选 **Lambda**：批处理层（Spark）做月度画像，加速层（Flink）做实时大屏，服务层合并两者。若只有实时统计需求，Kappa 更简单。
:::

## 二、其他高频问法

| 问法 | 答案要点 |
|---|---|
| 数据湖与数据仓库 | 数据湖存原始数据、读时建模、支持非结构化；数据仓库存清洗后数据、写时建模 |
| 物联网架构 | 感知层、网络层、平台层、应用层；边缘计算降低时延和带宽 |
| 边缘计算的作用 | 就近处理、低时延、省带宽、数据隐私、离线可用 |
| 大模型应用的架构 | RAG（向量库检索 + 大模型生成）、Agent、私有化部署、缓存与路由降成本 |
| 数字孪生 | 物理实体建模、实时数据同步、仿真预测 |

:::write 大数据架构 | 300 | 10
某智慧交通平台需要：(1) 实时识别路口拥堵并在 5 秒内推送告警；(2) 每天夜间对全市一年的通行数据做出行规律分析。请设计数据处理架构并说明理由。
--- 要点
采用 Lambda 架构
加速层用 Kafka 加 Flink 实时计算拥堵并告警
批处理层用 HDFS 存全量数据，Spark 做夜间批量分析
服务层合并实时视图和批视图对外提供查询
理由：同时有实时和大量历史数据分析需求
--- 参考答案
采用 **Lambda 架构**。路口数据经 **Kafka** 接入；**加速层**用 **Flink** 实时计算拥堵指数，5 秒内推送告警；**批处理层**把全量数据存入 HDFS，夜间用 **Spark** 做一年数据的出行规律分析；**服务层**合并批视图与实时视图供查询。理由：系统**同时**有秒级实时需求和海量历史数据的复杂分析需求，Lambda 能兼顾实时性和准确性。
:::

:::cards 记忆卡
Lambda 的优势 :: 兼顾实时和准确，适合大量历史数据分析
Kappa 的优势 :: 只有一套流处理代码，架构简单
Kappa 的劣势 :: 历史数据重算效率低
数据湖 :: 存原始数据，读时建模
边缘计算的作用 :: 就近处理、低时延、省带宽
RAG :: 向量库检索相关知识，再让大模型生成
:::
