论文能不能写出来，关键在**考前准备好的项目素材**。一个准备充分的项目，可以套用到几乎所有论题。

## 一、选一个什么样的项目

- **真实**：最好是自己参与过的，细节经得起推敲；
- **有一定规模**：几十万到几百万元、几人到几十人、开发周期半年以上；
- **技术面广**：有 Web / 微服务 / 数据库 / 缓存 / 消息 / 安全等多方面的内容，便于对接不同论题；
- **角色**：写成系统架构师（或技术负责人），参与了架构设计和技术决策。

:::warn 没有大项目怎么办
可以把参与过的项目“**合理放大**”：真实的业务和技术为主，在规模、角色上适当加工；但要保持**前后一致**、技术细节真实，不要写自己完全不懂的技术。
:::

## 二、素材清单

:::check 我的项目素材
- 项目名称、建设单位、时间（起止年月）、投资规模、团队人数
- 项目背景：要解决的业务问题，原系统的痛点
- 系统功能：主要子系统和模块（5～8 个）
- 技术架构：分层、技术栈、部署方式（画一张架构图）
- 关键质量属性：性能、可用性、安全等的具体指标
- 我的角色和职责
- 3～5 个技术难点，以及你的解决方法
- 上线时间和量化效果（响应时间、并发、可用性、效率提升）
- 遗留的不足和改进方向
:::

在“论文写作”页面的“我的项目素材”里写好这些内容，每次写论文时就可以直接引用。

## 三、一个素材对接多个论题

| 论题 | 从项目中挑什么写 |
|---|---|
| 架构风格 | 分层架构、微服务、事件驱动在项目中的使用 |
| 架构评估 | 用 ATAM 评估过架构选型（效用树、风险点、权衡点） |
| 质量属性 | 性能（缓存、集群）、可用性（冗余）、安全（认证加密） |
| 微服务 / 云原生 | 服务拆分、治理、容器化部署 |
| 数据库 | 缓存、读写分离、分库分表、反规范化 |
| 可靠性 | 冗余、容错、故障恢复 |
| 安全 | 认证授权、加密、审计、等保 |

:::write 项目背景段 | 450
请用你准备的项目，写出论文正文的第一段“项目背景”（约 400 字），包括项目的来由、目标、规模、主要功能、技术架构概述和你的角色。
--- 要点
项目的单位、时间和背景（为什么要做）
项目目标和规模（投资、人数、周期）
主要功能模块
技术架构的简要描述
我的角色和职责
最后一句引出论题
:::

:::cards 记忆卡
论文项目的四个要求 :: 真实、有规模、技术面广、角色为架构师
