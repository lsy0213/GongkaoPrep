软件复用、基于构件的开发和模型驱动开发是架构设计的基础概念，每年约 1 题。

## 一、软件复用

- 可复用的不只是代码：**需求、设计、代码、测试用例、文档、架构、领域知识**都能复用；
- 分类：**垂直复用**（同一领域内）与**水平复用**（跨领域，如通用 GUI 库）；
- 好处：提高生产率、提高质量、降低成本、缩短周期。

## 二、基于构件的软件工程 CBSE

- **构件**：具有**规范接口**和明确上下文依赖、可以**独立部署**、可被第三方组装的软件单元；
- 构件的特性：**可组装、可部署、文档化、独立、标准化**；
- 构件开发的过程：**构件资格鉴定**（评估是否满足要求）→ **构件适配**（解决不匹配）→ 构件组装 → 构件演化；
- 构件适配的三种方式：**白盒包装**（修改源码）、**灰盒包装**（用构件扩展语言或 API）、**黑盒包装**（引入前后处理）。

:::key 构件检索的方法
**关键字分类法**（树状分类）、**刻面分类法**（多个维度描述）、**超文本组织方法**、属性值分类法。
:::

| 标准 | 厂商 / 组织 |
|---|---|
| **EJB** | Java EE（Sun / Oracle） |
| **COM / DCOM / COM+** | 微软 |
| **CORBA** | OMG，跨语言跨平台，ORB（对象请求代理）是核心 |

## 四、模型驱动开发 MDA

- OMG 提出，核心思想：**模型是开发的核心**，代码由模型转换生成；
- 三类模型：**CIM**（计算无关模型，业务）→ **PIM**（平台无关模型）→ **PSM**（平台相关模型）→ 代码；
- 关键是**模型转换**，PIM 一次建模，可转成多种平台的 PSM；
- 支持标准：UML、MOF（元对象设施）、XMI、CWM。

## 五、逆向工程与再工程

| 概念 | 含义 |
|---|---|
| **逆向工程** | 分析已有程序，得到更高抽象层次的表示（设计、需求），**不改变系统** |
| 设计恢复 | 逆向工程的子领域，从代码中恢复设计信息 |
| **重构** | 在同一抽象层次上改变表示形式，**不改变外部行为** |
| **再工程** | 逆向工程 + 修改 + 正向工程，重新实现系统 |

逆向工程导出的信息分 4 个级别：**实现级**（语法树、符号表）、**结构级**（调用图、结构图）、**功能级**（数据流、控制流）、**领域级**（实体关系模型）。
