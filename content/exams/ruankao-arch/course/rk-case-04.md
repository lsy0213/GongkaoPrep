数据库题是选做题里**最推荐**的，问法集中在：**Redis 缓存**、**反规范化**、**读写分离与分库分表**、**关系库与 NoSQL 的对比**、**数据一致性**。

## 一、高频问法与答案要点

| 问法 | 答案要点 |
|---|---|
| Redis 和 MySQL 怎么分工 | 热点数据、会话、计数放 Redis；持久数据、事务放 MySQL |
| Redis 的持久化方式 | RDB 快照、AOF 日志，比较优缺点 |
| Redis 的数据类型选择 | 排行榜用 ZSet，对象用 Hash，队列用 List，去重用 Set |
| 缓存穿透 / 击穿 / 雪崩 | 现象 + 对策（见数据库课程第 9 课） |
| 缓存与数据库一致性 | 先更新数据库再删除缓存；延迟双删；订阅 binlog 异步更新 |
| 反规范化的手段 | 增加冗余列、派生列、重新组表、分割表 |
| 反规范化的问题与对策 | 数据不一致 → 触发器、应用同步、批处理 |
| 读写分离的问题 | 主从延迟导致读到旧数据 → 关键读走主库、延迟检测 |
| 分库分表的问题 | 分布式事务、跨库 JOIN、全局 ID、分页排序 |
| 关系库 vs NoSQL | 一致性、事务、扩展性、模式灵活性对比 |

## 二、对比题的写法

:::example 关系库还是 MongoDB
某系统要存储结构差异很大的商品属性，问用关系库还是 MongoDB。
--- 关系库
强一致、支持事务和复杂查询；但属性结构多变时要频繁改表结构，或用 EAV 设计，查询复杂
--- MongoDB
文档模型，**模式灵活**，不同商品可以有不同字段；易于**水平扩展**；但事务和多表关联能力较弱
--- 结论
商品属性用 **MongoDB** 存储；订单、库存等需要强一致事务的数据仍用关系库。
:::

:::write 缓存设计 | 300 | 10
某电商系统商品详情页访问量很大，计划引入 Redis 缓存。请说明：(1) 读写缓存的流程；(2) 如何避免缓存雪崩。
--- 要点
读：先查缓存，命中直接返回；未命中查数据库并写入缓存
写：先更新数据库，再删除缓存
过期时间加随机值，避免同时失效
Redis 集群或哨兵保证缓存高可用
限流降级，保护数据库
多级缓存（本地缓存加 Redis）
--- 参考答案
(1) **读**：先查 Redis，命中则返回；未命中则查数据库，并把结果写入 Redis（设置过期时间）。**写**：先更新数据库，再**删除**缓存，下次读时重建（Cache Aside）。(2) 防雪崩：过期时间加**随机值**错开失效；Redis 采用**哨兵或集群**保证高可用；对数据库访问**限流、降级**；使用**本地缓存 + Redis 多级缓存**。
:::

:::cards 记忆卡
