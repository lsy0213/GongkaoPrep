质量管理、风险管理、配置管理都是概念题，记关键词即可。配置管理和架构师的日常工作关系最紧密。

## 一、质量管理

| 过程 | 要点 |
|---|---|
| 规划质量管理 | 确定质量标准，**成本效益分析**、质量成本 |
| **管理质量**（质量保证） | 审计**过程**是否按规范执行，关注过程改进 |
| **控制质量** | 检查**产品**是否符合要求，关注结果 |

常用工具：**因果图**（鱼骨图，找原因）、**帕累托图**（80/20，找主要问题）、**控制图**（判断过程是否稳定）、直方图、散点图、核查表、流程图。

## 二、风险管理

:::flow 风险管理过程
规划风险管理 :: 制定风险管理计划
识别风险 :: 头脑风暴、德尔菲法、核查表、SWOT；产出**风险登记册**
定性分析 :: **概率和影响矩阵**，排定优先级
定量分析 :: **决策树**、**蒙特卡洛模拟**、敏感性分析（龙卷风图）、预期货币价值 EMV
规划应对 :: 消极风险：**规避、转移、减轻、接受**；积极风险（机会）：开拓、分享、提高、接受
实施与监督 :: 跟踪已识别风险，识别新风险
:::

- 风险的特点：**不确定性**（可能发生也可能不发生）和**损失**；
- 风险暴露（风险曝光度）= **风险概率 × 风险损失**。

## 三、配置管理

- **配置项**：纳入配置管理的工作产品（需求文档、设计、代码、测试用例……）；
- **基线**：通过正式评审、**冻结**的配置项集合，作为后续工作的基础；基线的修改要走**变更控制**；
- 三个库：**开发库**（动态库，开发人员自由修改）、**受控库**（主库，基线存放处，修改要审批）、**产品库**（静态库，发布的产品）；
- 配置管理活动：**配置标识**、**变更控制**、**配置状态报告**、**配置审计**（功能审计、物理审计）、版本管理、发布管理；
- **变更控制委员会 CCB** 负责审批变更。

:::key 配置状态的变化
配置项的状态：**草稿**（版本号 0.YZ）→ **正式发布**（版本号 X.Y）→ **正在修改**（X.YZ），修改完成后再正式发布。
:::

## 四、沟通与干系人

- 沟通渠道数 = **n(n − 1) ÷ 2**（n 是人数）；
- 干系人管理：**权力 / 利益方格**——高权力高利益**重点管理**，高权力低利益**令其满意**，低权力高利益**随时告知**，低权力低利益**监督**。
