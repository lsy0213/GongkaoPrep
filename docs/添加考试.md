# 添加一门考试

软件里每门考试是一个**考试包**：`content/exams/<id>/`。公考（`gongkao`）和软考 · 系统架构设计师（`ruankao-arch`）就是两个现成的例子。
加一门新考试，最少只要写一个 `exam.json`；想要教程、复习计划、专属页面、资料整理，再按下面的顺序逐步加。

## 一、最小可用：只写清单

复制 `content/exams/ruankao-arch/exam.json` 到 `content/exams/<新 id>/exam.json`，改这些字段：

| 字段 | 说明 |
|---|---|
| `id` | 包名，和文件夹同名，只用小写字母、数字和 `-` |
| `order` | 在考试切换器和“全部考试”页里的顺序 |
| `family` / `level` / `name` / `short` | 考试大类（软考）、级别（高级）、名称、侧栏上的简称 |
| `emblem` / `color` | 切换器上的单字徽标和主色 |
| `brand_sub` / `title` / `desc` | 侧栏副标题、窗口标题、考试卡片上的一句话 |
| `subjects` | 科目：`id`、`name`、`full`（满分）、`pass`（合格线）、`type`（choice / case / essay）、`desc` |
| `sessions` | 考试场次：名称、包含的科目、时长 |
| `modules` | 题库的知识模块（章节刷题、统计、错题按它分）：`name`、`short`、`desc` |
| `ai` | AI 助教的身份：`system`（系统提示词）、`domain`、`focus`；教程里“动笔写”用哪种批改方式写在 `write_kind`（`rkcase` = 案例题，不写就是申论批改） |
| `planner` | 复习计划模块的名字（见第四节），不写就没有每日任务 |
| `nav` | 侧栏菜单：`{"route", "label", "glyph"}`，分组用 `{"sec", "label", "items": [...]}`，分隔线 `{"sep": true}` |
| `routes` | 路由 → 页面模块：`"practice": "practice"` 用通用页面，`"case": "rk/case"` 用 `web/js/pages/rk/case.js` |
| `bottom_nav` | 手机底栏：`[路由, 文字, 图标, [属于这一栏的路由…]]` |
| `timer` | 专注计时可选的科目和简称 |
| `settings` | 这门考试自己的设置项和默认值（`exam_date`、`start_date`、`daily_hours`、资料文件夹……），保存在这门考试自己的库里 |

保存后重启软件，侧栏顶部的考试切换器里就有了新考试。下面这些通用页面不用写代码就能用：
章节刷题（`practice`）、错题本（`wrong`）、闪卡（`cards`）、学习统计（`stats`）、笔记本（`memo`）、AI 助教（`ai`）、设置（`settings`）、系统教程（`learn`）、复习计划（`plan`）、全部考试（`exams`）。

## 二、数据怎么分

- 学习记录在 `<数据目录>/exams/<id>/app.db`，整理好的资料在 `<数据目录>/exams/<id>/library/`；公考仍是原来的 `app.db` 和 `library/`；
- 打卡、笔记本、AI 设置和用量、外观是所有考试共用的（`exams.SHARED_TABLES`、`exams.GLOBAL_PREFS`）；
- 当前考试由界面的 Cookie `gk_exam` 决定，每个请求在 `server.Handler.guard` 里设好；后台任务没有请求，一律当作公考，整理别的考试的资料时要显式传考试 id；
- 导出备份会带上考试 id，导入时不能导进另一门考试。

## 三、内容：题库、教程、闪卡

| 内容 | 放在哪里 |
|---|---|
| 内置练习题 | `content/exams/<id>/questions/*.json`（格式同 README“导入更多题目”，`module` 用清单里的模块名） |
| 整理出来的真题 | `<数据目录>/exams/<id>/library/questions.db`，用 `qdb.replace_kind(..., path=...)` 写入 |
| 系统教程 | `content/exams/<id>/course/`：`index.json` + 每课一个 `.md` + `maps/`（总导图、课程导图、本课导图），写法和公考教程相同 |
| 闪卡 | 学完的课里的记忆卡自动进“教程知识卡”；另外的卡组放 `content/exams/<id>/cards/*.json` |

教程写完后检查：

```bash
python tools/check_course.py --exam <id>
python tools/draft_lesson_maps.py --exam <id>   # 给还没有本课导图的课起草导图，再人工删改
```

`index.json` 里可以加 `"texts"`，替换教程首页和总导图页上的说明文字、搜索框的热门词（见软考的 `index.json`）。
真题演练块 `:::practice 模块 | 考点 | 题数 | 来源` 里的模块和考点名，要和题库里的一致（软考的考点表在 `gongkao/ruankao/topics.py`）。

## 四、复习计划

在 `gongkao/<包>/plan.py` 写一个模块，提供和 `gongkao/planner.py` 一样的函数：
`phases(settings, today)`、`current_phase(settings, today)`、`milestones(settings, today)`、`tasks_for_day(settings, day, next_lessons)`、`week_preview(settings, today)`，
可选 `rhythm(settings, today)`（复习计划页的“每周节奏”）和 `FORM`（“调整计划”表单的字段）。
然后在 `gongkao/api/home.py` 的 `PLANNERS` 里登记，并在清单里写 `"planner": "<包>.plan"`。参考 `gongkao/ruankao/plan.py`。

每日任务的链接写成界面路由（`#/learn/<课 id>`、`#/practice?module=…&count=…`），要保证这些路由在清单的 `routes` 里。

## 五、专属页面和接口

- 页面：`web/js/pages/<包>/<页>.js`，导出 `render(el, ctx)`；在清单的 `routes` 里登记；
- 接口：`gongkao/api/<包>.py`，用 `@route` 登记（记得在 `gongkao/api/__init__.py` 里导入）；连接 `ctx.conn` 已经是当前考试的库；
- 图标：`web/js/icons.js` 按路由名取图标，没有就用清单里的 `glyph`；
- 样式：放 `web/css/exams.css`，颜色只用主题变量（`--surface`、`--ink`、`--brand`……），两套主题和深色模式就都能用。

## 六、整理资料

参考 `gongkao/ruankao/`：`catalog.py` 扫描分类、`papers.py` 拆真题、`build.py` 写题库和资料库、`topics.py` 归类考点。
资料文件夹在清单的 `settings` 里给默认值（比如 `library_root`），整理任务通过 `/api/<包>/jobs/start` 触发。
**购买的资料和由它整理出来的内容只放在数据目录里，不要放进仓库。**

## 七、检查清单

- [ ] 切换到新考试后，侧栏、首页、手机底栏都正常，切回公考一切照旧；
- [ ] 做题、错题、闪卡、学习时长只记在新考试里；打卡、笔记本是共用的；
- [ ] `python -m pytest`、`python -m ruff check .`、`python tools/check_frontend.py`、`python tools/check_course.py --exam <id>` 都通过；
- [ ] 打包：`GongkaoPrep.spec` 已经把整个 `content/` 和 `web/` 打进去；新的 Python 模块如果只通过字符串动态导入，要在 spec 的 `hiddenimports` 里补上。
